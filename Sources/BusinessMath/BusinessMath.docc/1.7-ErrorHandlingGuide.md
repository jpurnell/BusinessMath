# Error Handling Best Practices

Handle errors gracefully with comprehensive error types and actionable recovery suggestions.

## Overview

BusinessMath provides rich error handling with detailed error messages, recovery suggestions, error codes for tracking, and help links to documentation. When errors occur, you get not just a description of what went wrong, but specific guidance on how to fix it.

> **Note**: Every example in this guide compiles against the shipping API. Examples that mirror a
> passing test carry a `// Source: ErrorHandlingExamples.swift - <test>` comment; the rest are
> patterns you would write in your own code, using error cases the library defines.

This guide shows you how to:
- Understand BusinessMath error types and codes
- Handle errors with appropriate recovery strategies
- Aggregate multiple validation errors
- Create user-friendly error messages
- Debug errors effectively
- Choose when to throw vs. return optionals

## Why Enhanced Error Handling?

Traditional error messages are often cryptic:
```swift
// Traditional error
struct OpaqueError: Error { let message: String }

throw OpaqueError(message: "Invalid input")  // What's invalid? How do I fix it?
```

Enhanced errors provide context and guidance:
```swift
// Enhanced error
throw BusinessMathError.invalidInput(
    message: "Discount rate must be between 0 and 1",
    value: "-0.5",
    expectedRange: "0.0 to 1.0"
)

// Provides:
// - Clear description: "Invalid input: Discount rate must be between 0 and 1 (provided: -0.5) (expected: 0.0 to 1.0)"
// - Recovery suggestion: "Please provide a value within the range: 0.0 to 1.0"
// - Error code: E001
// - Help link: businessmath.com/errors/E001
```

## Error Type Categories

BusinessMath organizes errors into four categories:

| Category | Code Range | Examples |
|----------|------------|----------|
| **Calculation Errors** | E001-E099 | Invalid input, calculation failures, numerical instability |
| **Data Errors** | E100-E199 | Mismatched dimensions, data quality, missing data |
| **Model Errors** | E200-E299 | Invalid drivers, circular dependencies, inconsistent data |
| **Validation Errors** | E300-E399 | Validation failures, negative values, out of range |

## Calculation Errors (E001-E099)

### Invalid Input (E001)

Thrown when parameters are outside acceptable ranges:

```swift
// Source: ErrorHandlingExamples.swift - invalidInputNegativeRate()
let cashFlows = [-1000.0, 300.0, 400.0, 500.0]

do {
    // calculateNPV is the validating wrapper around npv(discountRate:cashFlows:)
    _ = try calculateNPV(discountRate: -0.5, cashFlows: cashFlows)
} catch let error as BusinessMathError {
    if case .invalidInput = error {
        print(error.errorDescription!)
        // "Invalid input: Invalid input parameter - discountRate must be non-negative. (provided: -0.5) (expected: ≥ 0.0)"

        print(error.recoverySuggestion!)
        // "Please provide a value within the range: ≥ 0.0"

        print("Error Code: \(error.code)")
        // "Error Code: E001"
    }
}
```

**Common Causes:**
- Negative values where positive required
- Values outside acceptable ranges
- Empty arrays where data required
- Invalid enum values

**Recovery Strategy:**
```swift
func calculateNPV(rate: Double, flows: [Double]) throws -> Double {
    // Validate before calculation
    guard rate >= 0 else {
        throw BusinessMathError.invalidInput(
            message: "Discount rate must be non-negative",
            value: String(rate),
            expectedRange: "≥ 0.0"
        )
    }

    guard !flows.isEmpty else {
        throw BusinessMathError.invalidInput(
            message: "Cash flows cannot be empty"
        )
    }

    return try calculateNPV(discountRate: rate, cashFlows: flows)
}
```

### Calculation Failed (E002)

Thrown when calculations don't converge or fail:

```swift
// Source: ErrorHandlingExamples.swift - calculationFailedIRR()
let allPositiveFlows = [100.0, 100.0, 100.0]  // All positive - no IRR!

do {
    _ = try irr(cashFlows: allPositiveFlows)
} catch let error as BusinessMathError {
    if case .calculationFailed(let operation, let reason, let suggestions) = error {
        print("\(operation) failed: \(reason)")
        // "IRR calculation failed: No valid IRR exists for all-positive cash flows"

        print("Suggestions:")
        for suggestion in suggestions {
            print("  • \(suggestion)")
        }
        // • Ensure cash flows include both negative (investments) and positive (returns)
        // • Check that initial investment is negative
        // • Verify cash flow signs are correct
    }
}
```

**Recovery Strategies:**
```swift
// Try with a different initial guess
func irrWithFallbackGuess(flows: [Double]) throws -> Double {
    do {
        return try irr(cashFlows: flows, guess: 0.1)
    } catch {
        // Try a different guess
        return try irr(cashFlows: flows, guess: 0.5)
    }
}

// Or adjust convergence parameters
func irrWithTightConvergence(flows: [Double]) throws -> Double {
    return try irr(
        cashFlows: flows,
        guess: 0.1,
        tolerance: 0.0001,
        maxIterations: 200
    )
}
```

### Division by Zero (E003)

Thrown when division by zero is attempted:

```swift
// Source: ErrorHandlingExamples.swift - divisionByZero()
do {
    _ = try growthRate(from: 0, to: 100)  // From zero!
} catch let error as BusinessMathError {
    if case .divisionByZero = error {
        print(error.errorDescription!)
        // "Division by zero in growth rate calculation"

        print(error.recoverySuggestion!)
        // Division by zero detected.
        // Check for:
        // • Zero revenue or zero base values
        // • Percentage calculations with zero denominators
        // • Missing data being treated as zero

        print("Error Code: \(error.code)")
        // "Error Code: E003"
    }
}
```

**Prevention:**
```swift
func calculateGrowthRate(from: Double, to: Double) throws -> Double {
    guard from != 0 else {
        throw BusinessMathError.divisionByZero(
            context: "growth rate calculation"
        )
    }

    return (to - from) / from
}
```

**Common Functions That Throw for Division by Zero:**

Several statistical and financial functions throw `BusinessMathError.divisionByZero`:

```swift
// Sample inputs used by the calls below
let xSeries = [1.0, 1.0, 1.0]          // Zero variance
let ySeries = [2.0, 4.0, 6.0]
let flatValues = [5.0, 5.0, 5.0]       // Zero standard deviation

// Statistical functions
_ = try harmonicMean([60.0, 40.0, 0.0])   // Throws: contains zero (reciprocal calculation)
_ = try correlationCoefficient(xSeries, ySeries)  // Throws: if either array has zero variance
_ = try coefficientOfSkew(flatValues)     // Throws: if standard deviation is zero
_ = try contraharmonicMean(5.0, -5.0)     // Throws: sum equals zero
_ = try logarithmicMean(-1.0, 2.0)        // Throws: negative or zero values
_ = try weightedAverage(flatValues, weights: [0.0, 0.0, 0.0])  // Throws: weights sum to zero

// Financial ratios (standalone functions)
_ = try currentRatio(currentAssets: 100.0, currentLiabilities: 0.0)   // Throws
_ = try quickRatio(currentAssets: 100.0, inventory: 20.0, currentLiabilities: 0.0)  // Throws
_ = try debtToEquity(totalLiabilities: 100.0, shareholderEquity: 0.0)  // Throws
_ = try interestCoverage(earningsBeforeInterestAndTax: 100.0, interestExpense: 0.0)  // Throws
_ = try roi(gainFromInvestment: 100.0, costOfInvestment: 0.0)  // Throws
_ = try roe(netIncome: 100.0, shareholderEquity: 0.0)  // Throws
_ = try profitMargin(netIncome: 100.0, revenue: 0.0)  // Throws
_ = try inventoryTurnover(costOfGoodsSold: 100.0, averageInventory: 0.0)  // Throws
_ = try assetTurnover(netSales: 100.0, averageTotalAssets: 0.0)  // Throws
```

### Numerical Instability (E004)

For numerical precision issues. No BusinessMath API raises this case today — it is the case to
reach for in your own guards around a calculation that can overflow:

```swift
func compoundGrowth(base: Double, rate: Double, periods: Int) throws -> Double {
    var value = base
    for _ in 0..<periods {
        value *= (1 + rate)
    }

    guard value.isFinite else {
        throw BusinessMathError.numericalInstability(
            message: "Value overflow detected in compound growth calculation",
            suggestions: [
                "Use logarithmic transformation for large numbers",
                "Scale inputs to a smaller range",
                "Consider using higher precision types"
            ]
        )
    }

    return value
}

do {
    _ = try compoundGrowth(
        base: 1e200,  // Very large number
        rate: 0.99,
        periods: 1000
    )
} catch let error as BusinessMathError {
    if case .numericalInstability(let message, let suggestions) = error {
        print(message)
        // "Value overflow detected in compound growth calculation"

        for suggestion in suggestions {
            print("• \(suggestion)")
        }
        // • Use logarithmic transformation for large numbers
        // • Scale inputs to a smaller range
        // • Consider using higher precision types
    }
}
```

## Data Errors (E100-E199)

### Mismatched Dimensions (E100)

Thrown when array sizes don't match:

```swift
// Source: ErrorHandlingExamples.swift - mismatchedDimensionsTimeSeries()
let periods = [
    Period.month(year: 2025, month: 1),
    Period.month(year: 2025, month: 2),
    Period.month(year: 2025, month: 3)
]
let values = [100.0, 110.0]  // Only 2 values for 3 periods!

do {
    _ = try TimeSeries(validating: periods, values: values)
} catch let error as BusinessMathError {
    if case .mismatchedDimensions(let message, let expected, let actual) = error {
        print(error.errorDescription!)
        // "Mismatched dimensions: Periods and values must have same length (expected: 3, got: 2)"

        print("Expected: \(expected), Got: \(actual)")
        // Expected: 3, Got: 2
    }
}
```

**Prevention:**
```swift
// Use the validating initializer for safe construction
func createTimeSeries(periods: [Period], values: [Double]) throws -> TimeSeries<Double> {
    // Automatically validates and throws BusinessMathError.mismatchedDimensions
    return try TimeSeries(validating: periods, values: values)
}
```

### Data Quality (E101)

Thrown when data quality issues are detected (NaN, Infinity, missing values):

```swift
// Source: ErrorHandlingExamples.swift - dataQualityNaN()
let periodsWithNaN = [
    Period.month(year: 2025, month: 1),
    Period.month(year: 2025, month: 2),
    Period.month(year: 2025, month: 3)
]
let valuesWithNaN = [100.0, Double.nan, 120.0]  // Contains NaN!

let timeSeries = TimeSeries(periods: periodsWithNaN, values: valuesWithNaN)

// Option 1: Throwing validation
do {
    try timeSeries.validateAndThrow()
} catch let error as BusinessMathError {
    if case .dataQuality(let message, let context) = error {
        print(error.errorDescription!)
        // "Data quality issue: Time series contains NaN values at 1 position(s)"

        if let errorCount = context["errorCount"] {
            print("Total errors: \(errorCount)")
        }
    }
}

// Option 2: Non-throwing validation for detailed inspection
let result = timeSeries.validate()
if !result.isValid {
    print("Validation failed with \(result.errors.count) error(s)")
    for error in result.errors {
        print("  • \(error.message)")
        // "Time series contains NaN values at 1 position(s)"
    }
}
```

### Missing Data (E102)

Thrown when required data is missing:

```swift
// Source: ErrorHandlingExamples.swift - missingDataAccount()
let model = FinancialModel {
    RevenueAmount("Product Sales", 100_000)
    CostAmount("COGS", 60_000)
}

do {
    let q1 = Period.quarter(year: 2025, quarter: 1)
    _ = try model.getValue(account: "Marketing Expenses", period: q1)
} catch let error as BusinessMathError {
    if case .missingData(let account, let period) = error {
        print(error.errorDescription!)
        // "Missing data for 'Marketing Expenses' in period Q1 2025"

        print("Account: \(account), Period: \(period)")
        // Account: Marketing Expenses, Period: Q1 2025
    }
}
```

**Recovery Strategies:**
```swift
let period = Period.quarter(year: 2025, quarter: 1)

// Option 1: Provide default value with optional chaining
let revenue = (try? model.getValue(account: "Product Sales", period: period)) ?? 0.0

// Option 2: Check if account exists before accessing
let accountNames = model.revenueComponents.map { $0.name }
    + model.costComponents.map { $0.name }
if accountNames.contains("Marketing") {
    let marketing = try model.getValue(account: "Marketing", period: period)
    print(marketing)
}

// Option 3: Add the missing account to the model
let updatedModel = FinancialModel {
    RevenueAmount("Product Sales", 100_000)
    CostAmount("COGS", 60_000)
    CostAmount("Marketing Expenses", 15_000)  // Add missing account
}
```

### Insufficient Data (E103)

Thrown when not enough data points exist:

```swift
// Source: ErrorHandlingExamples.swift - insufficientDataRegression()
// Linear regression requires at least 2 points
let xValues = [1.0]
let yValues = [2.0]

do {
    _ = try linearRegression(xValues, yValues)
} catch {
    print("Linear regression failed: \(error)")
    // Linear regression requires at least 2 data points
}
```

**Prevention:**
`linearRegression` returns the fitted line as a function of x, so the wrapper returns
`(Double) -> Double` rather than a coefficient tuple:

```swift
func performRegression(xValues: [Double], yValues: [Double]) throws -> (Double) -> Double {
    // Validate before calling regression
    guard xValues.count >= 2 && yValues.count >= 2 else {
        throw BusinessMathError.insufficientData(
            required: 2,
            actual: min(xValues.count, yValues.count),
            context: "Linear Regression"
        )
    }

    guard xValues.count == yValues.count else {
        throw BusinessMathError.mismatchedDimensions(
            message: "X and Y values must have same length",
            expected: String(xValues.count),
            actual: String(yValues.count)
        )
    }

    return try linearRegression(xValues, yValues)
}
```

## Model Errors (E200-E299)

### Invalid Driver (E200)

For invalid driver configuration. Driver initializers do not validate their inputs, so wrap
construction in a factory that does:

```swift
func makeGrowthDriver(name: String, value: Double) throws -> DeterministicDriver<Double> {
    guard value >= 0 else {
        throw BusinessMathError.invalidDriver(
            name: name,
            reason: "Growth rate cannot be negative"
        )
    }
    return DeterministicDriver(name: name, value: value)
}

do {
    _ = try makeGrowthDriver(name: "Revenue Growth", value: -0.5)
} catch let error as BusinessMathError {
    if case .invalidDriver(let name, let reason) = error {
        print("\(name): \(reason)")
        print(error.errorDescription!)
        // "Invalid driver 'Revenue Growth': Growth rate cannot be negative"

        print(error.recoverySuggestion!)
        // "Ensure all driver values are positive. Check input data for errors."
    }
}
```

### Circular Dependency (E201)

For circular references between accounts. Nothing in BusinessMath detects cycles for you, but
``FormulaEvaluator/accountNames(in:)`` reports what a formula reads without evaluating it, which
is enough to walk a definition set and find a cycle before any data is loaded:

```swift
// A depends on B, B depends on C, C depends on A — circular!
let circularDefinitions = [
    "A": "B * 1.2",
    "B": "C * 0.8",
    "C": "A * 0.5"
]

func dependencies(of account: String, in definitions: [String: String]) throws -> [String] {
    guard let formula = definitions[account] else { return [] }
    return try FormulaEvaluator<Double>.accountNames(in: formula).sorted()
}

do {
    var path = ["A"]
    while let next = try dependencies(of: path[path.count - 1], in: circularDefinitions).first {
        path.append(next)
        if next == path[0] {
            throw BusinessMathError.circularDependency(path: path)
        }
    }
} catch let error as BusinessMathError {
    if case .circularDependency(let path) = error {
        print(error.errorDescription!)
        // "Circular dependency detected: A → B → C → A"

        print(error.recoverySuggestion!)
        // Break the circular dependency by:
        // • Reordering calculations
        // • Introducing an intermediate value
        //
        // Dependency path: A → B → C → A

        print(path.joined(separator: " → "))
    }
}
```

**Solutions:**
```swift
// Solution 1: Break the cycle by reading a prior-period account instead of this period's B
let brokenWithLag = [
    "A": "PriorB * 1.2",
    "B": "C * 0.8",
    "C": "A * 0.5"
]

// Solution 2: Introduce an intermediate value both branches can read
let brokenWithIntermediate = [
    "A": "BaseValue * Factor",
    "B": "C * 0.8",
    "C": "BaseValue * 0.5"
]

// Either way, check the definitions before you use them
for definitions in [brokenWithLag, brokenWithIntermediate] {
    for (name, formula) in definitions.sorted(by: { $0.key < $1.key }) {
        let reads = try FormulaEvaluator<Double>.accountNames(in: formula).sorted()
        print("\(name) reads \(reads.joined(separator: ", "))")
    }
}
```

### Inconsistent Data (E202)

For data that doesn't match logical constraints. Raise it from your own consistency checks:

```swift
func validateBalanceSheetEquation(
    assets: Double,
    liabilities: Double,
    equity: Double,
    tolerance: Double = 0.01
) throws {
    let liabilitiesAndEquity = liabilities + equity
    guard abs(assets - liabilitiesAndEquity) <= tolerance else {
        throw BusinessMathError.inconsistentData(
            description: "Total Assets (\(assets)) ≠ Liabilities + Equity (\(liabilitiesAndEquity))"
        )
    }
}

do {
    try validateBalanceSheetEquation(
        assets: 1_000_000,
        liabilities: 600_000,
        equity: 350_000
    )
} catch let error as BusinessMathError {
    if case .inconsistentData(let description) = error {
        print(description)
        print(error.errorDescription!)
        // "Data inconsistency: Total Assets ($1,000,000) ≠ Liabilities + Equity ($950,000)"

        print(error.recoverySuggestion!)
        // "Review your data for logical consistency and correct any discrepancies"
    }
}
```

## Validation Errors (E300-E399)

### Validation Failed (E300)

Thrown when multiple validation errors occur:

``ErrorAggregator`` collapses two or more collected errors into a single
`validationFailed`:

```swift
func validateModel(
    _ model: FinancialModel,
    discountRate: Double,
    cashFlows: [Double]
) throws {
    var aggregator = ErrorAggregator()

    if model.calculateRevenue() <= 0 {
        aggregator.add(BusinessMathError.invalidInput(
            message: "Revenue must be positive"
        ))
    }

    if discountRate < 0 || discountRate > 1 {
        aggregator.add(BusinessMathError.outOfRange(
            value: discountRate,
            min: 0.0,
            max: 1.0,
            context: "Discount rate"
        ))
    }

    if cashFlows.isEmpty {
        aggregator.add(BusinessMathError.invalidInput(
            message: "Cash flows array cannot be empty"
        ))
    }

    try aggregator.throwIfNeeded()
}

do {
    try validateModel(FinancialModel(), discountRate: 1.5, cashFlows: [])
} catch let error as BusinessMathError {
    if case .validationFailed(let errors) = error {
        print("Validation failed with \(errors.count) error(s):")
        for message in errors {
            print("  • \(message)")
        }
        // • Invalid input: Revenue must be positive
        // • Value 1.5 out of range [0.0, 1.0] in Discount rate
        // • Invalid input: Cash flows array cannot be empty
    }
}
```

### Negative Value (E301)

For negative values where a positive one is required. Raise it from your own input guards:

```swift
func validatePrice(_ price: Double) throws -> Double {
    guard price >= 0 else {
        throw BusinessMathError.negativeValue(
            name: "Price",
            value: price,
            context: "Product pricing calculation"
        )
    }
    return price
}

do {
    _ = try validatePrice(-50.0)
} catch let error as BusinessMathError {
    if case .negativeValue(let name, let value, let context) = error {
        print("\(name) = \(value) in \(context)")
        print(error.errorDescription!)
        // "Negative value for 'Price' (-50.0) in Product pricing calculation"

        print(error.recoverySuggestion!)
        // 'Price' should not be negative.
        // Verify:
        // • Input data is correct
        // • Calculations are not producing unintended negative results
        // • Use absolute value if negative is mathematically possible but semantically invalid
    }
}
```

### Out of Range (E302)

For values outside an acceptable range. Raise it from your own range guards:

```swift
func validateDiscountRate(_ rate: Double) throws -> Double {
    guard (0.0...1.0).contains(rate) else {
        throw BusinessMathError.outOfRange(
            value: rate,
            min: 0.0,
            max: 1.0,
            context: "Discount rate validation"
        )
    }
    return rate
}

do {
    _ = try validateDiscountRate(1.5)
} catch let error as BusinessMathError {
    if case .outOfRange(let value, let min, let max, let context) = error {
        print("\(value) not in [\(min), \(max)] for \(context)")
        print(error.errorDescription!)
        // "Value 1.5 out of range [0.0, 1.0] in Discount rate validation"

        print(error.recoverySuggestion!)
        // "Adjust the value to fall within the valid range [0.0, 1.0]"
    }
}
```

## Error Aggregation

### Collecting Multiple Errors

Use ``ErrorAggregator`` to collect validation errors:

```swift
// Source: ErrorHandlingExamples.swift - errorAggregation()
var aggregator = ErrorAggregator()

let reportedRevenue = -100.0
let dcfDiscountRate = 1.5
let emptyCashFlows: [Double] = []

// Collect multiple errors
if reportedRevenue < 0 {
    aggregator.add(BusinessMathError.negativeValue(
        name: "Revenue",
        value: reportedRevenue,
        context: "Income Statement"
    ))
}

if dcfDiscountRate < 0 || dcfDiscountRate > 1 {
    aggregator.add(BusinessMathError.outOfRange(
        value: dcfDiscountRate,
        min: 0.0,
        max: 1.0,
        context: "DCF Valuation"
    ))
}

if emptyCashFlows.isEmpty {
    aggregator.add(BusinessMathError.invalidInput(
        message: "Cash flows cannot be empty"
    ))
}

// Throw if any errors collected
do {
    try aggregator.throwIfNeeded()
} catch let error as BusinessMathError {
    if case .validationFailed(let errors) = error {
        print("Validation failed with \(errors.count) error(s)")
        // Validation failed with 3 error(s)
    }
}
```

### Comprehensive Model Validation

```swift
func validateFinancialModel(_ model: FinancialModel) throws {
    var aggregator = ErrorAggregator()

    // A model's accounts are its revenue and cost components; both carry an
    // optional multi-period series alongside the single-period amount.
    let series: [(name: String, timeSeries: TimeSeries<Double>?)] =
        model.revenueComponents.map { ($0.name, $0.timeSeries) }
        + model.costComponents.map { ($0.name, $0.timeSeries) }

    // Validate accounts
    for account in series {
        guard let values = account.timeSeries?.valuesArray else { continue }

        if values.contains(where: { $0.isNaN }) {
            aggregator.add(BusinessMathError.dataQuality(
                message: "NaN values in \(account.name)"
            ))
        }

        if values.isEmpty {
            aggregator.add(BusinessMathError.missingData(
                account: account.name,
                period: "all"
            ))
        }
    }

    // Validate periods
    let periodCounts = Set(series.compactMap { $0.timeSeries?.periods.count })
    if periodCounts.count > 1 {
        aggregator.add(BusinessMathError.mismatchedDimensions(
            message: "All accounts must have the same number of periods"
        ))
    }

    // Throw if any issues found
    try aggregator.throwIfNeeded()
}
```

`FinancialModel` carries revenue and cost components, not a balance sheet, so the
accounting-equation check lives on ``BalanceSheet`` instead — `try balanceSheet.validate(tolerance: 0.01)`
throws `BalanceSheetError.accountingEquationViolation` per offending period. Catch it and
re-add it to the same aggregator if you want one combined report.

## User-Facing Error Messages

### Creating Friendly Error Messages

```swift
func handleError(_ error: Error) -> String {
    guard let mathError = error as? BusinessMathError else {
        return "An unexpected error occurred"
    }

    var message = mathError.errorDescription ?? "Unknown error"

    // Add user-friendly context
    switch mathError {
    case .invalidInput:
        message = "⚠️ Invalid Input\n\n\(message)"

    case .calculationFailed:
        message = "❌ Calculation Failed\n\n\(message)"

    case .divisionByZero:
        message = "⚠️ Division by Zero\n\n\(message)"

    case .missingData:
        message = "📊 Missing Data\n\n\(message)"

    case .circularDependency:
        message = "🔄 Circular Dependency\n\n\(message)"

    case .validationFailed:
        message = "✗ Validation Failed\n\n\(message)"

    default:
        message = "Error\n\n\(message)"
    }

    // Add recovery suggestion
    if let recovery = mathError.recoverySuggestion {
        message += "\n\n💡 How to Fix:\n\(recovery)"
    }

    // Add error code for support
    message += "\n\nError Code: \(mathError.code)"

    return message
}

// Stand-ins for your app's calculation and presentation layers
func performCalculation() throws -> Double {
    try calculateNPV(discountRate: -0.5, cashFlows: [-1000, 300, 400, 500])
}

func showAlert(title: String, message: String) {
    print("[\(title)] \(message)")
}

// Usage
do {
    let result = try performCalculation()
    print("NPV: \(result)")
} catch {
    let userMessage = handleError(error)
    showAlert(title: "Error", message: userMessage)
}
```

### Logging Errors with Context

BusinessMath extends `OSLog`'s `Logger` with a shared instance. `Logger.error` takes a single
message, so fold the structured fields into it:

```swift
import OSLog

func logError(_ error: Error, context: [String: String] = [:]) {
    func format(_ fields: [String: String]) -> String {
        fields.sorted { $0.key < $1.key }
            .map { "\($0.key)=\($0.value)" }
            .joined(separator: " ")
    }

    let message: String
    if let mathError = error as? BusinessMathError {
        let fields = [
            "errorCode": mathError.code,
            "recovery": mathError.recoverySuggestion ?? "None",
            "helpAnchor": mathError.helpAnchor ?? ""
        ].merging(context) { $1 }

        message = "\(mathError.errorDescription ?? "Unknown error") \(format(fields))"
    } else {
        message = "\(error.localizedDescription) \(format(context))"
    }

    // BusinessMathError payloads carry no user data, so the message is safe to surface.
    Logger.shared.error("\(message, privacy: .public)")
}

// Usage
let rate = -0.5
let flows = [-1000.0, 300.0, 400.0, 500.0]

do {
    let result = try calculateNPV(rate: rate, flows: flows)
    print("NPV: \(result)")
} catch {
    logError(error, context: [
        "function": "calculateNPV",
        "rate": String(rate),
        "flowCount": String(flows.count)
    ])
    throw error
}
```

## Best Practices

### 1. Throw Early, Validate Thoroughly

```swift
// GOOD: Validate at entry point
func calculateIRR(cashFlows: [Double]) throws -> Double {
    // Validate immediately
    guard !cashFlows.isEmpty else {
        throw BusinessMathError.invalidInput(
            message: "Cash flows cannot be empty"
        )
    }

    guard cashFlows.contains(where: { $0 < 0 }) && cashFlows.contains(where: { $0 > 0 }) else {
        throw BusinessMathError.calculationFailed(
            operation: "IRR",
            reason: "Cash flows must contain both positive and negative values",
            suggestions: [
                "Ensure initial investment is negative",
                "Verify cash flow signs are correct"
            ]
        )
    }

    return try irr(cashFlows: cashFlows)
}

// BAD: Defer validation, get cryptic errors later
func calculateIRRWithoutValidation(cashFlows: [Double]) throws -> Double {
    return try irr(cashFlows: cashFlows)  // May throw unclear error
}
```

### 2. Provide Actionable Recovery Suggestions

```swift
// GOOD: Specific, actionable suggestions
throw BusinessMathError.calculationFailed(
    operation: "NPV",
    reason: "Discount rate too high causing numerical overflow",
    suggestions: [
        "Use a discount rate below 1.0 (100%)",
        "Check if discount rate is in decimal form (0.10 for 10%)",
        "Scale cash flows to smaller values"
    ]
)

// BAD: Vague, unhelpful suggestions
throw BusinessMathError.calculationFailed(
    operation: "NPV",
    reason: "Calculation error",
    suggestions: ["Try different values"]
)
```

### 3. Choose Throwing vs. Optional Appropriately

**Use `throws` when:**
- The error is unexpected and needs handling
- Callers should know something went wrong
- Recovery is possible with different inputs

```swift
func calculateIRRThrowing(cashFlows: [Double]) throws -> Double {
    // Throws because caller needs to handle invalid input
    return try irr(cashFlows: cashFlows)
}
```

**Use `Optional` when:**
- The absence of a value is normal
- No error condition exists
- Caller can handle nil naturally

```swift
func findAccount(named: String, in accounts: [Account<Double>]) -> Account<Double>? {
    // Returns nil if not found - this is normal, not an error
    return accounts.first { $0.name == named }
}
```

### 4. Document Error Conditions

```swift
