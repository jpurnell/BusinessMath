# Grouped Ranking: What Predicts a Choice

Fit what predicts which candidates get chosen *within* each chooser's own set, test whether a refit beats the weights you already have, and keep the verdict honest.

## Overview

Some data has the shape "within each group, some candidates were chosen": a person and the colleagues they named, a shopper and the products they clicked, a query and the results someone opened. The question is what about a candidate predicts being chosen. A pooled regression answers a different question. It credits any feature that merely correlates with choosers who choose a lot, because a chooser who names fifteen people contributes fifteen positives and one who names two contributes two.

The grouped-ranking toolkit compares each group only with itself, so how much a group chooses drops out. It is in `Statistics/GroupedRanking`, generic over `T: Real & Sendable & BinaryFloatingPoint`, and additive: no existing symbol changed.

- ``GroupedChoiceData`` holds the groups, candidates with numeric features, and which were chosen (or in what order).
- ``GroupedChoiceModel`` pairs the data with **reference weights** and a ``ChoiceLikelihood``. ``GroupedChoiceModel/fit(groupWeights:penalty:frozen:start:maxIterations:)`` refits the weights, pulled toward the reference by a penalty.
- ``GroupRankingMetrics`` scores a set of candidate scores group by group.
- ``GroupedCrossValidation`` chooses the penalty, bootstraps over groups, and runs ``GroupedCrossValidation/heldOutComparison(model:penalties:minimumChosen:folds:innerFolds:resamples:level:seed:)``, which returns a ``HeldOutComparison``.
- ``LogisticRegression/fit(penalty:maxIterations:tolerance:)`` is a separate, penalised logistic fit.

Everything fitted here **ranks**. A candidate nobody chose is *unknown*, not rejected, so the weights say which candidates a chooser is more likely to choose, not by how much they are chosen.

## The data

A group is one chooser's candidates. Each candidate is a row of features and a flag.

```swift
let small = GroupedChoiceData<Double>(groups: [
    [(features: [1, 0], chosen: true), (features: [0, 1], chosen: false), (features: [0, 0], chosen: false)],
    [(features: [1, 1], chosen: true), (features: [0, 0], chosen: false)],
])
// small?.groupCount == 2, small?.featureCount == 2, small?.informativeGroups == [0, 1]
```

Initialisers return `nil` for malformed data. Features are stored sparsely (only the non-zero entries), so a wide, mostly-zero feature matrix costs memory in proportion to what is present. An optional fixed offset per candidate carries a term the model must not fit, such as a deduction you apply by rule.

A *group with no chosen candidate, or with every candidate chosen, has nothing to compare*; it is not an error, and it adds nothing to the fit (``GroupedChoiceData/informativeGroups`` lists the groups that do).

## Two likelihoods, not one

``ChoiceLikelihood`` has two cases, and they are different functions.

- ``ChoiceLikelihood/subset``: the group chose an *unordered* set of candidates, the **conditional logit**. How many a group chose does not move the weights.
- ``ChoiceLikelihood/ranking``: the group ranked its top candidates *in order*, the **Plackett-Luce** model. Each next choice is made among the candidates not yet taken.

With exactly one chosen candidate per group they coincide. With more than one they do not, and Plackett-Luce taken over an arbitrary order of an unordered set would make the answer depend on the order chosen. So each model refuses the other's data:

```swift
let ranked = GroupedChoiceData<Double>(rankedGroups: [
    (candidates: [[1, 0], [0, 1], [0, 0]], ranking: [0, 1]),   // candidate 0 first, then 1
    (candidates: [[1, 1], [0, 0], [1, 0]], ranking: [0, 2]),
    (candidates: [[0, 1], [1, 0], [0, 0]], ranking: [1]),
])
// GroupedChoiceModel(data: ranked, reference: [1, 1], likelihood: .ranking) is a model;
// the same data with .subset is nil, and unordered data with .ranking is nil.
```

## Fitting around a reference

Most uses start from weights somebody already believes in. The model fits two things: one **scale** that turns the reference weights into log-odds, then a **multiplier** on each weight (at least zero), with a penalty on how far a multiplier moves from 1. A large penalty returns your weights; a small one approaches the unpenalised optimum. The data has to argue for any change.

The example below builds 60 choosers with six candidates each. Feature 0 genuinely drives the choice; feature 1 does not. The reference weights say both matter equally.

```swift
var generator = SplitMix64(seed: 11)
let groups: [[(features: [Double], chosen: Bool)]] = (0..<60).map { _ in
    let candidates: [[Double]] = (0..<6).map { _ in
        [Double.random(in: 0..<1, using: &generator) < 0.4 ? 1 : 0,
         Double.random(in: 0..<1, using: &generator) < 0.4 ? 1 : 0]
    }
    let appeal: [Double] = candidates.map { exp(1.5 * $0[0]) }
    var pick = Double.random(in: 0..<1, using: &generator) * appeal.reduce(0, +)
    var chosenIndex = appeal.count - 1
    for (index, share) in appeal.enumerated() {
        if pick < share { chosenIndex = index; break }
        pick -= share
    }
    return candidates.enumerated().map { (features: $0.element, chosen: $0.offset == chosenIndex) }
}

guard let data = GroupedChoiceData<Double>(groups: groups),
      let model = GroupedChoiceModel(data: data, reference: [1, 1], likelihood: .subset) else {
    fatalError("the example's data is well-formed")
}
let weights = [Double](repeating: 1, count: data.groupCount)   // every group counts once
let fit = try model.fit(groupWeights: weights, penalty: 0.05)
// fit.multipliers  ≈ [1.69, 0.27]  (the real feature is raised, the other lowered)
// fit.scale        ≈ 0.785  (effective weights ≈ 1.32 and 0.21, against a true 1.5 and 0)
// fit.converged    true
```

`fit` **throws** ``GroupedChoiceError/didNotConverge(iterations:gradientNorm:)`` if the search does not settle. It never returns an unsettled estimate as though it had settled.

The penalty acts on each multiplier's *relative* change. A feature whose reference is `0` cannot move, because its multiplier is not identified. ``GroupedChoiceModel/referenceFit(groupWeights:)`` keeps every multiplier at 1 and fits only the scale: the reference weights, calibrated.

## Ranking metrics, group by group

``GroupRankingMetrics/perGroup(scores:data:k:)`` takes one score per candidate row and returns, for each group, where its chosen candidates fell.

```swift
if let scores = model.scores(for: fit),
   let perGroup = GroupRankingMetrics.perGroup(scores: scores, data: data, k: 3) {
    let summary = GroupRankingMetrics.summary(perGroup)
    // summary.groups         60
    // summary.meanPercentile ≈ 0.65   (0.5 is chance)
    // summary.topOwnShare    ≈ 0.33          (the share of a group's chosen candidates inside its top *n*, *n* being how many it chose)
}
```

``GroupRankingMetrics/pooledEvaluation(scores:data:)`` pools the comparable groups and hands the result to ``ClassifierEvaluation``, so the ROC area and the confusion matrix are the library's own.

A metric is `nil` where it is not defined: scores that are not one per row, a group with nothing to compare, a score that is not finite.

## Does a refit beat what you had?

Fitting on the data you score flatters the refit. ``GroupedCrossValidation/heldOutComparison(model:penalties:minimumChosen:folds:innerFolds:resamples:level:seed:)`` holds each group out of the fit exactly once, picks the penalty on the training groups only (nested folds), and compares the refit with the reference weights on the groups it never saw.

```swift
let comparison = GroupedCrossValidation.heldOutComparison(
    model: model, penalties: [.reference, .penalty(0.05), .penalty(0.5)], minimumChosen: 10,
    folds: 5, innerFolds: 3, resamples: 200, level: 0.9, seed: 1)
// comparison?.referencePercentile  ≈ 0.63
// comparison?.refitPercentile      ≈ 0.65
// comparison?.difference           ≈ 0.023
// comparison?.lower, comparison?.upper   ≈ 0.003, 0.045   (90% bootstrap interval over groups)
// comparison?.refitBeatsReference  true
```

``HeldOutComparison`` states a **fact**: the two mean percentiles, their paired difference, and a bootstrap interval for the difference over *groups* (never rows). It does not say whether to adopt anything. ``HeldOutComparison/refitBeatsReference`` is true when the interval's lower end is above zero; ``HeldOutComparison/intervalExcludesZero`` is true on either side. How big a move counts, and how many chosen candidates a feature needs before it is refitted (`minimumChosen`, which keeps a thin feature at its reference value), belong to your own policy and sit on top of these figures.

Seeds are `UInt64` values. The fold assignment, each inner assignment and the bootstrap use derived seeds from `SplitMix64`, so a run repeats exactly.

## A penalised logistic regression

``LogisticRegression/fit(maxIterations:tolerance:)`` refuses data a feature separates perfectly, because the coefficient would run to infinity. A small ridge penalty fixes that:

```swift
let regression = LogisticRegression<Double>(predictors: [[0], [1], [2], [3]],
                                            outcomes: [false, false, true, true])
// regression.fit() throws LogisticRegressionError.separation
let logisticFit = try regression.fit(penalty: LogisticPenalty(lambda: 0.1))
// logisticFit.coefficients  ≈ [-3.98, 2.65]   (intercept, then slope)
// logisticFit.probability([1.5])  ≈ 0.5
```

``LogisticPenalty`` is `(lambda / 2) × Σ (β − centre)²`, with the intercept left unpenalised and a centre of zero by default. The result is a ``PenalisedLogisticFit``, not a `LogisticFit`: it has **no classical standard errors**, because they are not valid under a penalty. Use a bootstrap. The existing unpenalised `fit` and its errors are unchanged.

A constant outcome is still refused when an intercept is fitted, since the unpenalised intercept would diverge.

## What it does not do

- It estimates **rankings, not probabilities**. A candidate nobody chose is unknown; the fitted weights say who is more likely to be chosen, not how likely.
- It does **not** decide whether to adopt a refit. ``HeldOutComparison`` reports; you decide.
- The penalty on the grouped models acts on the *relative* change of each reference weight. ``LogisticRegression`` has no reference weights, so its penalty is a coefficient-space ridge.
- The MCP tools for this toolkit are a later phase, in businessMathMCP.
