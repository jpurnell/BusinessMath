# Financial Statements API Reference

Complete API documentation for the role-based financial statement system including all enumerations, properties, and methods.

## Overview

This document provides comprehensive API reference for BusinessMath's financial statement system. For a tutorial-style introduction with step-by-step examples, see <doc:3.5-FinancialStatementsGuide>.

BusinessMath provides a **role-based financial statement system** that models real-world accounting, where one account can appear in more than one statement under a different role in each.

### Key Features

- ✅ **Multi-Role Support**: Accounts can have roles in multiple statements (Income Statement, Balance Sheet, Cash Flow Statement)
- ✅ **Flexible Design**: A single `accounts:` parameter for statement construction, with automatic categorization
- ✅ **Type-Safe**: Generic over the numeric type — `Account<T: Real & Sendable>`, with `T: Codable`
- ✅ **Validated**: Entity and period consistency are checked when a statement is constructed
- ✅ **Materialized Views**: Pre-compute aggregated metrics for repeated reads

### Architecture

```
Entity (Company/Division)
   ↓
Account<T> (with one or more roles)
   ↓
Statement (IncomeStatement, BalanceSheet, or CashFlowStatement)
   ↓
Statement.Materialized (pre-computed aggregations, nested inside each statement type)
```

### How this document stays true

The three role tables below are **generated by executing the library**, not written by hand. A
generator (`docref`) compiles a throwaway program against the built module, iterates
`allCases`, and records what each `is…` predicate actually returns; the category column is
derived from that truth table, and the descriptions come from the doc comments on the cases
themselves. A companion `docref check` mode fails if the tables in this file no longer match the
code, so a role that is renamed, added, or reclassified cannot quietly leave this page wrong.

Content between `<!-- generated:… -->` markers is machine-written. Everything else on this page
is hand-written and is checked a different way: every Swift block here is compiled against the
library as a single program, so a symbol that does not exist cannot survive in an example.

## Core Concepts

### 1. Entity

Represents a company, division, or business unit.

<!-- docs:illustrative -->
```swift
// Quoted from Financial Statements/Entity.swift — shown for reference, not compiled here.
public struct Entity: Hashable, Codable, Sendable {
    public let id: String
    public let primaryIdentifierType: EntityIdentifierType
    public let name: String
    public var identifiers: [EntityIdentifierType: String]
    public var currency: String?
    public var fiscalYearEnd: MonthDay?
    public var metadata: [String: String]

    public init(
        id: String,
        primaryType: EntityIdentifierType = .internal,
        name: String,
        identifiers: [EntityIdentifierType: String] = [:],
        currency: String? = nil,
        fiscalYearEnd: MonthDay? = nil,
        metadata: [String: String] = [:]
    )
}
```

Note the asymmetry, which is easy to get wrong: the initializer label is `primaryType:`, but the
stored property you read back is `primaryIdentifierType`.

```swift
let entity = Entity(
    id: "EXAMPLE",
    primaryType: .internal,
    name: "Example Corp"
)

let identifierType = entity.primaryIdentifierType   // .internal
```

Two entities are equal when their `id` values match, which is what makes them usable as
dictionary keys in ``ConsolidatedStatements``.

**Entity identifier types.** `EntityIdentifierType` is deliberately *not* generated: it is not
`CaseIterable`, and `custom(String)` carries an associated value, so there is no finite list a
program could print. The list below is hand-maintained, and the code block underneath it is the
guard — it names every case, so removing or renaming one breaks the build of this article.

| Case | Meaning |
| --- | --- |
| `.ticker` | Stock ticker symbol (e.g. `"AAPL"`) |
| `.cusip` | CUSIP number, for securities identification |
| `.isin` | International Securities Identification Number |
| `.lei` | Legal Entity Identifier, ISO 17442 |
| `.internal` | Internal company or system identifier |
| `.taxId` | Tax identification number (EIN, VAT, …) |
| `.custom(String)` | Any scheme without a dedicated case |

There is no `.sedol` case. A SEDOL is expressed as `.custom("SEDOL")`, which is the intended
route for every identifier scheme the enum does not name.

```swift
let identifierTypes: [EntityIdentifierType] = [
    .ticker,
    .cusip,
    .isin,
    .lei,
    .internal,
    .taxId,
    .custom("SEDOL")
]
```

### 2. Period

A `Period` is a **struct**, not an enum: a `PeriodType` paired with a reference date. Periods are
built through factory methods rather than cases.

<!-- docs:illustrative -->
```swift
// Quoted from Time Series/Period.swift — shown for reference, not compiled here.
public struct Period: Hashable, Comparable, Codable, Sendable {
    public let type: PeriodType
    public let date: Date

    public static func millisecond(year: Int, month: Int, day: Int,
                                   hour: Int, minute: Int, second: Int, millisecond: Int) -> Period
    public static func second(year: Int, month: Int, day: Int,
                              hour: Int, minute: Int, second: Int) -> Period
    public static func minute(year: Int, month: Int, day: Int, hour: Int, minute: Int) -> Period
    public static func hour(year: Int, month: Int, day: Int, hour: Int) -> Period
    public static func day(_ date: Date) -> Period
    public static func month(year: Int, month: Int) -> Period
    public static func quarter(year: Int, quarter: Int) -> Period
    public static func year(_ year: Int) -> Period
}
```

`PeriodType` is an `Int`-raw-valued ladder, ordered from finest to coarsest, and is `Comparable`
on that order: `.millisecond` (0), `.second` (1), `.minute` (2), `.hourly` (3), `.daily` (4),
`.monthly` (5), `.quarterly` (6), `.annual` (7).

```swift
let q1 = Period.quarter(year: 2024, quarter: 1)
let q2 = Period.quarter(year: 2024, quarter: 2)
let q3 = Period.quarter(year: 2024, quarter: 3)
let q4 = Period.quarter(year: 2024, quarter: 4)
let periods = [q1, q2, q3, q4]

// Other granularities
let fiscal2024 = Period.year(2024)
let january2024 = Period.month(year: 2024, month: 1)
let oneDay = Period.day(Date())

// Periods know their own shape
let granularity = q1.type            // .quarterly
let quarterNumber = q1.quarter       // 1
let quarterLabel = q1.label          // display string
let finerThanAnnual = q1.type < PeriodType.annual   // true
```

A period can also be subdivided — `q1.months()`, `fiscal2024.quarters()`, `january2024.days()` —
which is how the same model is re-expressed at a different granularity.

### 3. TimeSeries

Generic time series data, keyed by period.

<!-- docs:illustrative -->
```swift
// Quoted from Time Series/TimeSeries.swift — shown for reference, not compiled here.
public struct TimeSeries<T: Real & Sendable>: Sequence, Sendable {
    public let periods: [Period]        // chronologically sorted
    public let metadata: TimeSeriesMetadata
    public let labels: [Period: String]?

    public init(periods: [Period], values: [T],
                metadata: TimeSeriesMetadata = TimeSeriesMetadata(),
                labels: [String]? = nil)

    public var valuesArray: [T] { get }
    public var count: Int { get }
    public subscript(period: Period) -> T? { get }
    public subscript(period: Period, default defaultValue: T) -> T { get }
}

extension TimeSeries: Codable where T: Codable { }
```

The values are stored privately in a `[Period: T]` dictionary. There is no public `values`
property; read them through `valuesArray`, which returns them in `periods` order, or by
subscripting a period.

```swift
let revenueSeries = TimeSeries(
    periods: periods,
    values: [100_000.0, 110_000.0, 120_000.0, 130_000.0]
)

let q1Value = revenueSeries[q1]              // Optional(100_000.0)
let safeQ1Value = revenueSeries[q1, default: 0]
let allValues = revenueSeries.valuesArray    // in periods order
let pointCount = revenueSeries.count
```

## Account API

### Creating Accounts

An account requires:

1. An `Entity` — which company or division it belongs to
2. A `name` — non-empty, and not only whitespace
3. **At least one role** — `incomeStatementRole`, `balanceSheetRole`, or `cashFlowRole`
4. A `TimeSeries` — non-empty

```swift
let productRevenue = try Account(
    entity: entity,
    name: "Product Revenue",
    incomeStatementRole: .productRevenue,
    timeSeries: revenueSeries
)
```

An account carrying only a balance sheet role:

```swift
let cashSeries = TimeSeries(
    periods: periods,
    values: [50_000.0, 60_000.0, 75_000.0, 90_000.0]
)

let cash = try Account(
    entity: entity,
    name: "Cash and Cash Equivalents",
    balanceSheetRole: .cashAndEquivalents,
    timeSeries: cashSeries
)
```

…and one carrying only a cash flow role:

```swift
let capexSeries = TimeSeries(
    periods: periods,
    values: [-8_000.0, -8_000.0, -9_000.0, -9_000.0]
)

let capex = try Account(
    entity: entity,
    name: "Capital Expenditures",
    cashFlowRole: .capitalExpenditures,
    timeSeries: capexSeries
)
```

### Multi-Role Accounts

Accounts can hold **more than one role**, which is how the same economic item reaches two
statements without being entered twice:

```swift
// Depreciation is an expense on the income statement and an add-back on the cash flow statement
let depreciationSeries = TimeSeries(
    periods: periods,
    values: [5_000.0, 5_000.0, 5_000.0, 5_000.0]
)

let depreciation = try Account(
    entity: entity,
    name: "Depreciation & Amortization",
    incomeStatementRole: .depreciationAmortization,
    cashFlowRole: .depreciationAmortizationAddback,
    timeSeries: depreciationSeries
)

// Inventory is a balance sheet asset whose period-over-period change is an operating cash flow
let inventorySeries = TimeSeries(
    periods: periods,
    values: [20_000.0, 22_000.0, 24_000.0, 26_000.0]
)

let inventory = try Account(
    entity: entity,
    name: "Inventory",
    balanceSheetRole: .inventory,
    cashFlowRole: .changeInInventory,
    timeSeries: inventorySeries
)
```

### Account Validation

Accounts validate on construction. Each of these throws:

```swift
// Throws AccountError.emptyTimeSeries
let emptySeriesAccount = try Account(
    entity: entity,
    name: "Revenue",
    incomeStatementRole: .revenue,
    timeSeries: TimeSeries<Double>(periods: [], values: [])
)

// Throws AccountError.invalidName
let blankNameAccount = try Account(
    entity: entity,
    name: "   ",
    incomeStatementRole: .revenue,
    timeSeries: revenueSeries
)

// Throws FinancialModelError.accountMustHaveAtLeastOneRole
let roleFreeAccount = try Account(
    entity: entity,
    name: "No Role Account",
    timeSeries: revenueSeries
)
```

the predicate that answers `true` for that case, so it is directly usable in a filter rather than
being a label you have to translate. Where a case answers to more than one predicate — a payable
is both a current liability and a working capital account — every applicable predicate is listed.

## Income Statement

### Creating an Income Statement

```swift
let serviceRevenue = try Account(
    entity: entity,
    name: "Service Revenue",
    incomeStatementRole: .serviceRevenue,
    timeSeries: TimeSeries(periods: periods, values: [20_000.0, 22_000.0, 24_000.0, 26_000.0])
)

let costOfGoodsSold = try Account(
    entity: entity,
    name: "Cost of Goods Sold",
    incomeStatementRole: .costOfGoodsSold,
    timeSeries: TimeSeries(periods: periods, values: [40_000.0, 42_000.0, 44_000.0, 46_000.0])
)

let researchAndDevelopment = try Account(
    entity: entity,
    name: "Research & Development",
    incomeStatementRole: .researchAndDevelopment,
    timeSeries: TimeSeries(periods: periods, values: [15_000.0, 16_000.0, 17_000.0, 18_000.0])
)

let incomeTaxExpense = try Account(
    entity: entity,
    name: "Income Tax Expense",
    incomeStatementRole: .incomeTaxExpense,
    timeSeries: TimeSeries(periods: periods, values: [6_000.0, 6_500.0, 7_000.0, 7_500.0])
)

let incomeStatement = try IncomeStatement(
    entity: entity,
    periods: periods,
    accounts: [
        productRevenue,
        serviceRevenue,
        costOfGoodsSold,
        researchAndDevelopment,
        depreciation,          // multi-role: also on the cash flow statement
        incomeTaxExpense
    ]
)
```

Every account passed in must carry an `incomeStatementRole`; one that does not raises
`FinancialModelError.accountMissingRole(statement:accountName:)`.

### Accessing Categorized Accounts

Accounts are categorized on read, from their roles:

```swift
let revenues = incomeStatement.revenueAccounts
let expenses = incomeStatement.expenseAccounts
let costOfRevenue = incomeStatement.costOfRevenueAccounts
let operatingExpenseAccounts = incomeStatement.operatingExpenseAccounts
let nonCashChargeAccounts = incomeStatement.nonCashChargeAccounts
let interestAccounts = incomeStatement.interestExpenseAccounts
let taxAccounts = incomeStatement.taxAccounts
```

`expenseAccounts` is defined as *every account with a role that is not revenue* — so it includes
non-operating items and tax, not only operating costs. There is no `isExpense` predicate on the
role enum; the complement of `isRevenue` is what the statement uses.

### Computed Metrics

```swift
let totalRevenue = incomeStatement.totalRevenue
let totalExpenses = incomeStatement.totalExpenses
let netIncome = incomeStatement.netIncome              // totalRevenue - totalExpenses
let grossProfit = incomeStatement.grossProfit          // revenue - cost of revenue
let operatingExpenseTotal = incomeStatement.operatingExpenses
let operatingIncome = incomeStatement.operatingIncome  // gross profit - opex - non-cash charges
let ebitda = incomeStatement.ebitda                    // operating income + non-cash charges
```

Margins are available on the same basis:

```swift
let grossMargin = incomeStatement.grossMargin
let operatingMargin = incomeStatement.operatingMargin
let netMargin = incomeStatement.netMargin
let ebitdaMargin = incomeStatement.ebitdaMargin
```

> Important: There is **no `ebit` property**. `operatingIncome` is the closest equivalent — its
> doc comment describes it as EBIT — and it is computed after depreciation and amortization, so
> it is not interchangeable with `ebitda`. If you need EBIT under a different definition than
> "gross profit less operating expenses less non-cash charges", compute it yourself from the
> account collections above rather than assuming a property exists.

### Cost Behaviour

Where accounts carry `AccountMetadata` marking them fixed or variable, the statement will
separate them:

```swift
let variableCosts = incomeStatement.totalVariableCosts
let fixedCosts = incomeStatement.totalFixedCosts
let contributionMargin = incomeStatement.contributionMargin
let contributionMarginPercent = incomeStatement.contributionMarginPercent
let operatingLeverage = incomeStatement.operatingLeverage()
```

### Accessing Values by Period

```swift
let q1Revenue = totalRevenue[q1]      // Optional
let q1NetIncome = netIncome[q1]       // Optional
```

### Materialization

`materialize()` returns a nested `Materialized` value — `IncomeStatement<T>.Materialized`, not a
free-standing `MaterializedIncomeStatement` — in which every aggregate is a stored property
rather than a recomputed one:

```swift
let materializedIncome: IncomeStatement<Double>.Materialized = incomeStatement.materialize()

let storedRevenue = materializedIncome.totalRevenue
let storedNetIncome = materializedIncome.netIncome
let storedEbitda = materializedIncome.ebitda
```

### Balance Sheet Validation

The accounting equation is **not** enforced at construction, so a partial balance sheet is a
legal value:

```swift
let partialBalanceSheet = try BalanceSheet(
    entity: entity,
    periods: periods,
    accounts: [cash, accountsReceivable]   // assets only
)
```

When you do want the equation checked, ask for it. `validate(tolerance:)` throws
`BalanceSheetError.accountingEquationViolation(period:assets:liabilitiesAndEquity:)` for the
first period that fails:

```swift
do {
    try balanceSheet.validate(tolerance: 0.01)
} catch let error as BalanceSheetError {
    print("Balance sheet did not validate: \(error)")
} catch {
    print("Unexpected error: \(error)")
}
```

### Creating a Cash Flow Statement

```swift
let netIncomeAccount = try Account(

let cashFlowStatement = try CashFlowStatement(

    accounts: [
        netIncomeAccount,
        depreciation,        // multi-role: expense on the income statement
        accountsReceivable,  // multi-role: asset on the balance sheet
        inventory,           // multi-role: asset on the balance sheet
        accountsPayable,     // multi-role: liability on the balance sheet
        capex
    ]
)
```

### Accessing Categorized Accounts

```swift
let operatingAccounts = cashFlowStatement.operatingAccounts
let investingAccounts = cashFlowStatement.investingAccounts
let financingAccounts = cashFlowStatement.financingAccounts
```

### Computed Metrics

```swift
let operatingCF = cashFlowStatement.operatingCashFlow
let investingCF = cashFlowStatement.investingCashFlow
let financingCF = cashFlowStatement.financingCashFlow
let netCF = cashFlowStatement.netCashFlow        // operating + investing + financing
let freeCF = cashFlowStatement.freeCashFlow      // operating + investing
```

Free cash flow is the sum of operating and investing cash flow, not a subtraction: investing
cash flow is already negative when the business is buying assets.

### Working Capital Changes

Some cash flow roles describe a *balance* rather than a flow. For those, the statement takes the
period-over-period difference before aggregating, so you can feed it the same balance sheet
series you already have. `usesChangeInBalance` is the predicate that marks them:

```swift
let balanceDrivenRoles = CashFlowRole.allCases.filter { $0.usesChangeInBalance }

let workingCapitalChanges = cashFlowStatement.workingCapitalChanges
let workingCapitalByComponent = cashFlowStatement.workingCapitalChangesByComponent
```

The membership of `balanceDrivenRoles` is listed in the generated cash flow table above; it is
not restated here, because a restatement is the thing that goes stale.

## Multi-Role Accounts

### Common Multi-Role Patterns

#### 1. Depreciation & Amortization

An expense on the income statement, an add-back on the cash flow statement. The `depreciation`
account defined earlier carries both roles, and is passed to both statements unchanged.

#### 2. Stock-Based Compensation

The same shape as depreciation:

```swift
let stockCompSeries = TimeSeries(
    periods: periods,
    values: [3_000.0, 3_200.0, 3_400.0, 3_600.0]
)

let stockComp = try Account(
    entity: entity,
    name: "Stock-Based Compensation",
    incomeStatementRole: .stockBasedCompensation,
    cashFlowRole: .stockBasedCompensationAddback,
    timeSeries: stockCompSeries
)
```

#### 3. Working Capital Accounts

Balance sheet assets and liabilities whose movement is an operating cash flow —
`accountsReceivable`, `inventory`, and `accountsPayable` above each pair a `balanceSheetRole`
with the matching `change…` cash flow role.

#### 4. Three-Role Accounts

Rare, but permitted:

```swift
let complexAccount = try Account(
    entity: entity,
    name: "Debt Service",
    incomeStatementRole: .interestExpense,
    balanceSheetRole: .longTermDebt,
    cashFlowRole: .repaymentOfDebt,
    timeSeries: TimeSeries(periods: periods, values: [4_000.0, 4_000.0, 4_000.0, 4_000.0])
)
```

## Complete Example

### Building a Three-Statement Model

Everything above, assembled once, in a single function so the model is self-contained:

```swift
func buildThreeStatementModel() throws {
    // 1. Entity and periods
    let corp = Entity(id: "MODEL", primaryType: .internal, name: "Model Corp")
    let quarters = [
        Period.quarter(year: 2024, quarter: 1),
        Period.quarter(year: 2024, quarter: 2),
        Period.quarter(year: 2024, quarter: 3),
        Period.quarter(year: 2024, quarter: 4)
    ]

    // 2. Revenue
    let product = try Account(
        entity: corp,
        name: "Product Revenue",
        incomeStatementRole: .productRevenue,
        timeSeries: TimeSeries(periods: quarters, values: [100_000.0, 110_000.0, 120_000.0, 130_000.0])
    )
    let service = try Account(
        entity: corp,
        name: "Service Revenue",
        incomeStatementRole: .serviceRevenue,
        timeSeries: TimeSeries(periods: quarters, values: [20_000.0, 22_000.0, 24_000.0, 26_000.0])
    )

    // 3. Costs
    let cogs = try Account(
        entity: corp,
        name: "Cost of Goods Sold",
        incomeStatementRole: .costOfGoodsSold,
        timeSeries: TimeSeries(periods: quarters, values: [40_000.0, 42_000.0, 44_000.0, 46_000.0])
    )
    let rnd = try Account(
        entity: corp,
        name: "Research & Development",
        incomeStatementRole: .researchAndDevelopment,
        timeSeries: TimeSeries(periods: quarters, values: [15_000.0, 16_000.0, 17_000.0, 18_000.0])
    )

    // 4. Multi-role: income statement + cash flow statement
    let dna = try Account(
        entity: corp,
        name: "Depreciation & Amortization",
        incomeStatementRole: .depreciationAmortization,
        cashFlowRole: .depreciationAmortizationAddback,
        timeSeries: TimeSeries(periods: quarters, values: [5_000.0, 5_000.0, 5_000.0, 5_000.0])
    )

    // 5. Balance sheet accounts, two of them multi-role
    let bank = try Account(
        entity: corp,
        name: "Cash and Cash Equivalents",
        balanceSheetRole: .cashAndEquivalents,
        timeSeries: TimeSeries(periods: quarters, values: [50_000.0, 60_000.0, 75_000.0, 90_000.0])
    )
    let receivables = try Account(
        entity: corp,
        name: "Accounts Receivable",
        balanceSheetRole: .accountsReceivable,
        cashFlowRole: .changeInReceivables,
        timeSeries: TimeSeries(periods: quarters, values: [30_000.0, 35_000.0, 40_000.0, 45_000.0])
    )
    let stock = try Account(
        entity: corp,
        name: "Inventory",
        balanceSheetRole: .inventory,
        cashFlowRole: .changeInInventory,
        timeSeries: TimeSeries(periods: quarters, values: [20_000.0, 22_000.0, 24_000.0, 26_000.0])
    )
    let debt = try Account(
        entity: corp,
        name: "Long-Term Debt",
        balanceSheetRole: .longTermDebt,
        timeSeries: TimeSeries(periods: quarters, values: [100_000.0, 95_000.0, 90_000.0, 85_000.0])
    )
    let shares = try Account(
        entity: corp,
        name: "Common Stock",
        balanceSheetRole: .commonStock,
        timeSeries: TimeSeries(periods: quarters, values: [50_000.0, 50_000.0, 50_000.0, 50_000.0])
    )

    // 6. Income statement
    let income = try IncomeStatement(
        entity: corp,
        periods: quarters,
        accounts: [product, service, cogs, rnd, dna]
    )

    // 7. Balance sheet
    let position = try BalanceSheet(
        entity: corp,
        periods: quarters,
        accounts: [bank, receivables, stock, debt, shares]
    )

    // 8. Cash flow statement, seeded with net income from the income statement
    let bottomLine = try Account(
        entity: corp,
        name: "Net Income",
        cashFlowRole: .netIncome,
        timeSeries: income.netIncome
    )
    let flows = try CashFlowStatement(
        entity: corp,
        periods: quarters,
        accounts: [bottomLine, dna, receivables, stock]
    )

    // 9. Read it back
    let firstQuarter = quarters[0]
    print("Q1 2024 Summary:")
    print("  Revenue:      \(income.totalRevenue[firstQuarter]?.currency() ?? "N/A")")
    print("  Net Income:   \(income.netIncome[firstQuarter]?.currency() ?? "N/A")")
    print("  Total Assets: \(position.totalAssets[firstQuarter]?.currency() ?? "N/A")")
    print("  Operating CF: \(flows.operatingCashFlow[firstQuarter]?.currency() ?? "N/A")")
    print("  Free CF:      \(flows.freeCashFlow[firstQuarter]?.currency() ?? "N/A")")
}
```

## Best Practices

### 1. Materialize When You Read Repeatedly

Aggregates on a live statement are computed on every access. If you are walking periods,
materialize once first:

```swift
func summarizeSlowly(_ statement: IncomeStatement<Double>) {
    for period in statement.periods {
        _ = statement.totalRevenue[period]      // recomputes the aggregate every time
        _ = statement.totalExpenses[period]
        _ = statement.netIncome[period]
    }
}

func summarizeQuickly(_ statement: IncomeStatement<Double>) {
    let snapshot = statement.materialize()      // computed once
    for period in snapshot.periods {
        _ = snapshot.totalRevenue[period]
        _ = snapshot.totalExpenses[period]
        _ = snapshot.netIncome[period]
    }
}
```

### 2. Keep One Entity per Statement

Every account in a statement must belong to the same entity, and construction throws if not:

```swift
func demonstrateEntityConsistency() throws {
    let north = Entity(id: "NORTH", primaryType: .internal, name: "North Division")
    let south = Entity(id: "SOUTH", primaryType: .internal, name: "South Division")
    let quarters = [Period.quarter(year: 2024, quarter: 1)]

    let northRevenue = try Account(
        entity: north,
        name: "Revenue",
        incomeStatementRole: .revenue,
        timeSeries: TimeSeries(periods: quarters, values: [100.0])
    )
    let southRevenue = try Account(
        entity: south,
        name: "Revenue",
        incomeStatementRole: .revenue,
        timeSeries: TimeSeries(periods: quarters, values: [80.0])
    )

    do {
        _ = try IncomeStatement(entity: north, periods: quarters, accounts: [northRevenue, southRevenue])
    } catch FinancialModelError.entityMismatch(let expected, let found, let accountName) {
        print("\(accountName): expected \(expected), found \(found)")
    }
}
```

### 3. Cover Every Period

Each account must have data for every period the statement declares. The error names the account
and the periods it is missing:

```swift
func demonstratePeriodConsistency() throws {
    let corp = Entity(id: "PERIODS", primaryType: .internal, name: "Periods Corp")
    let quarters = [
        Period.quarter(year: 2024, quarter: 1),
        Period.quarter(year: 2024, quarter: 2),
        Period.quarter(year: 2024, quarter: 3)
    ]

    let full = try Account(
        entity: corp,
        name: "Revenue",
        incomeStatementRole: .revenue,
        timeSeries: TimeSeries(periods: quarters, values: [100.0, 110.0, 120.0])
    )
    let short = try Account(
        entity: corp,
        name: "Operating Expenses",
        incomeStatementRole: .operatingExpenseOther,
        timeSeries: TimeSeries(periods: Array(quarters.prefix(2)), values: [50.0, 55.0])
    )

    do {
        _ = try IncomeStatement(entity: corp, periods: quarters, accounts: [full, short])
    } catch FinancialModelError.periodMismatch(let accountName, let missing) {
        print("\(accountName) is missing \(missing.count) period(s)")
    }
}
```

### 4. Filter on the Role Predicates

The role enums answer questions about themselves, which is cheaper and safer than matching on
names:

```swift
func classify(_ account: Account<Double>) {
    if account.incomeStatementRole?.isRevenue == true {
        print("\(account.name): revenue")
    }
    if account.incomeStatementRole?.isCostOfRevenue == true {
        print("\(account.name): cost of revenue")
    }
    if account.incomeStatementRole?.isNonCashCharge == true {
        print("\(account.name): non-cash charge")
    }
    if account.balanceSheetRole?.isCurrentAsset == true {
        print("\(account.name): current asset")
    }
    if account.balanceSheetRole?.isWorkingCapital == true {
        print("\(account.name): working capital")
    }
    if account.balanceSheetRole?.isDebt == true {
        print("\(account.name): debt")
    }
    if account.cashFlowRole?.isOperating == true {
        print("\(account.name): operating cash flow")
    }
    if account.cashFlowRole?.usesChangeInBalance == true {
        print("\(account.name): driven by change in balance")
    }
}
```

### 5. Name Accounts as They Are Reported

```swift
let regionalRevenue = try Account(
    entity: entity,
    name: "Product Revenue - North America",
    incomeStatementRole: .productRevenue,
    timeSeries: revenueSeries
)
```

A name like `"Rev1"` will construct perfectly well and tell you nothing later.

### 6. Handle Missing Data Explicitly

The period subscript is optional, and the default-supplying overload exists for when zero is the
right answer:

```swift
func describeRevenue(_ series: TimeSeries<Double>, in period: Period) {
    if let value = series[period] {
        print("Revenue: \(value.currency())")
    } else {
        print("Revenue: no data")
    }

    let withDefault = series[period, default: 0]
    print("Revenue (defaulted): \(withDefault.currency())")
}
```

### 7. Choose a Numeric Type That Conforms to `Real`

`Account<T>` and `TimeSeries<T>` require `T: Real & Sendable`, and `Account` additionally
requires `T: Codable`. In practice that means the binary floating-point types:

```swift
let doubleSeries = TimeSeries<Double>(
    periods: periods,
    values: [100_000.0, 110_000.0, 120_000.0, 130_000.0]
)
let doubleAccount = try Account(
    entity: entity,
    name: "Revenue (Double)",
    incomeStatementRole: .revenue,
    timeSeries: doubleSeries
)

let floatSeries = TimeSeries<Float>(
    periods: periods,
    values: [100_000, 110_000, 120_000, 130_000]
)
let floatAccount = try Account(
    entity: entity,
    name: "Revenue (Float)",
    incomeStatementRole: .revenue,
    timeSeries: floatSeries
)
```

`Double` is the right default for financial amounts. `Float` halves the memory at the cost of
about seven significant digits, which is enough for large simulations and not enough for a
ledger.

Neither `Int` nor `Decimal` conforms to `Real`, so neither can be used here — these do **not**
compile:

<!-- docs:illustrative -->
```swift
// error: type 'Int' does not conform to protocol 'Real'
let unitAccount = try Account<Int>(...)

// error: type 'Decimal' does not conform to protocol 'Real'
let preciseAccount = try Account<Decimal>(...)
```

For unit counts, model them as `Double` and rely on exact integer representation up to 2^53. For
exact decimal arithmetic, keep the `Decimal` values outside the statement types and convert at
the boundary.
