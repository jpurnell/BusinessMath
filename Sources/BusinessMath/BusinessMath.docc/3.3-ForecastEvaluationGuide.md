# Forecast Evaluation & Diagnostics

Decide whether a series is forecastable at all, measure forecasts honestly out-of-sample, and diagnose what structure remains.

## Overview

BusinessMath's forecasting models (``LinearTrend``, ``ExponentialTrend``,
``HoltWintersModel``, ``MovingAverageModel``, …) tell you *what* a forecast is. This
tier tells you whether to *trust* it.

The motivation is a structural fact about time series: **forecasting is extrapolation,
not interpolation.** The test period always lies outside the training window's support,
so a model that fits history well can still fail out-of-sample — and an in-sample error
bar will not warn you. Worse, many real business series (exchange rates, demand with
regime shifts, credit spreads) carry so little exploitable signal that *no* model beats
a naive baseline. The honest workflow is therefore:

1. **Measure forecastability first** — is there structure to exploit?
2. **Benchmark against naive** — does the model actually beat "repeat last (season)"?
3. **Evaluate out-of-sample** — with rolling-origin backtesting, never in-sample fit.
4. **Diagnose** — did the model extract the autocorrelation? Is the series stationary?
5. **Quantify uncertainty honestly** — with empirical, backtest-derived intervals.

## The example series

Every snippet below runs against these four series, so they are worth defining once.
`sales` (and its alias `monthlySales`) is strongly seasonal; `exchangeRate` is a
low-signal path with no exploitable season.

```swift
// Four years of monthly periods, 2021-01 … 2024-12.
let periods = (0..<48).map { Period.month(year: 2021 + $0 / 12, month: $0 % 12 + 1) }

// Level + trend + a 12-month seasonal cycle.
let seasonalValues = (0..<48).map { i -> Double in
	100 + 1.5 * Double(i) + 20 * Foundation.sin(2 * Double.pi * Double(i) / 12)
}

// A deterministic pseudo-random walk: drifting, aseasonal, low forecastability.
let walkValues: [Double] = (0..<48).reduce(into: [Double]()) { path, i in
	let previous = path.last ?? 1.20
	path.append(previous + Foundation.sin(Double(i) * 12.9898) * 0.02)
}

let sales = TimeSeries(periods: periods, values: seasonalValues)
let monthlySales = sales                                       // the seasonal regime
let exchangeRate = TimeSeries(periods: periods, values: walkValues)  // the noise regime
let revenue = TimeSeries(periods: periods, values: seasonalValues.map { $0 * 1_000 })

// A 36-month training window carved out of the same series.
let history = TimeSeries(
	periods: Array(periods.prefix(36)),
	values: Array(seasonalValues.prefix(36))
)
```

## The Forecaster protocol

Everything here is model-agnostic. Any type conforming to ``Forecaster`` — including the
built-in models and the baselines below — plugs into the same harness.

```swift
let forecast = try LinearTrend<Double>().trainedForecast(from: history, horizon: 12)
```

``Forecaster`` carries an optional `exogenous` parameter (``ForecastRegressors``) that is
unused today; it reserves the API so driver-based forecasting can be added later without
a breaking change. Wrap an ad-hoc rule with ``AnyForecaster``.

## Step 1 — Should I even model this?

``TimeSeries/forecastability(seasonLength:)`` returns a ``ForecastabilityReport`` whose
`spectralEntropy` runs from 0 (a single dominant frequency — highly forecastable) to 1
(a flat spectrum — white noise). The `verdict` buckets it as `.strong`, `.moderate`,
`.weak`, or `.noise`.

```swift
let report = try revenue.forecastability()
if report.verdict == .noise {
    print("This series is indistinguishable from noise — do not trust point forecasts.")
}
```

To *enforce* this, use ``TimeSeries/requireForecastable(maxSpectralEntropy:)``, or pass a
`.strict` ``RefusalPolicy`` to the backtest so it throws
``BacktestError/unforecastableSeries(spectralEntropy:threshold:)`` rather than producing
plausible-but-wrong numbers.

## Step 2 — Beating the naive baseline

The benchmarks are the yardstick, not the goal:

- ``NaiveForecaster`` — carry the last value forward.
- ``SeasonalNaiveForecaster`` — repeat the last full season.
- ``DriftForecaster`` — extend the average slope.

A forecast is only worth its complexity if it beats these. The scaled error
``TimeSeries/mase(against:training:seasonLength:)`` encodes exactly that: **MASE < 1**
means the forecast beats the (seasonal-)naive benchmark; **MASE ≈ 1** means it does not.

## Step 3 — Out-of-sample backtesting

``TimeSeries/backtest(_:config:)`` runs rolling-origin (walk-forward) cross-validation.
At each origin the forecaster trains only on data *before* the origin and is scored
against the true future — no leakage, ever.

```swift
let config = BacktestConfig(initialTrainSize: 36, horizon: 6, step: 6, seasonLength: 12)
let result = try sales.backtest(HoltWintersModel<Double>(seasonalPeriods: 12), config: config)
print("Out-of-sample MASE:", result.mase ?? .nan)   // < 1 ⇒ beats seasonal-naive
```

The ``BacktestReport`` carries pooled out-of-sample `rmse`/`mae`/`mape`/`mase`, per-fold
detail, and `residualsByHorizon` (feeding Step 5). Choose `.expanding` or
`.sliding(length:)` windows; omit `seasonLength` to let the ACF suggest it.

## Step 4 — Diagnostics

**Did the model extract the signal?** ``TimeSeries/autocorrelation(maxLag:)`` and
``TimeSeries/partialAutocorrelation(maxLag:)`` expose the ACF/PACF; run
``TimeSeries/ljungBox(lags:fittedParameters:)`` on the residuals — if it
`rejectsWhiteNoise(alpha:)`, structure remains unexploited.

**Must I difference first?** Stationarity is a prerequisite for learnability. Run both
``TimeSeries/augmentedDickeyFuller(lag:)`` (H0: unit root) and
``TimeSeries/kpss(regression:lag:)`` (H0: stationary). Because their null hypotheses are
opposite, agreement is a confident verdict; each result carries a plain-language
`recommendation` (e.g. "difference (d=1) before fitting").

## Step 5 — Honest uncertainty

``BacktestReport/empiricalIntervals(around:confidenceLevel:)`` builds prediction bands
from the empirical quantiles of the out-of-sample residuals at each horizon — so they
widen with horizon *as the data actually did*, unlike the parametric in-sample bands on
``LinearTrend/projectWithConfidence(periods:confidenceLevel:)`` and
``HoltWintersModel/predictWithConfidence(periods:confidenceLevel:)``.

```swift
let point = try HoltWintersModel<Double>(seasonalPeriods: 12).trainedForecast(from: sales, horizon: 6)
let bands = try result.empiricalIntervals(around: point, confidenceLevel: 0.95)
```

## Worked example: two regimes

The library can reproduce the central finding of the time-series-forecasting literature
using only these APIs. On a **strongly-seasonal** series, spectral entropy is low and
seasonal-aware methods crush plain naive. On a **low-forecastability** series (e.g. a
chaotic/event-driven path), spectral entropy is high and *every* model — simple or not —
clusters around naive (MASE ≈ 1).

```swift
let seasonal = try monthlySales.forecastability()   // → .strong / .moderate, low entropy
let fx = try exchangeRate.forecastability()          // → .noise / .weak, high entropy
```

The lesson matches the theory: where forecastability is low, the lift comes not from a
fancier model but from **exogenous drivers** — which is why ``Forecaster`` is already
shaped to accept them.
