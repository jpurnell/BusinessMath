# Quasi-Random Sampling

Placing sample points on purpose instead of at random, and what a distribution has to
be able to say before you can.

## Overview

A Monte Carlo estimate converges as `1/√n`. Quadrupling the iterations halves the
error, which is a poor exchange and the reason large simulations are large.

The cost is not randomness itself but *clumping*. Independent draws leave gaps and
pile up in clusters; much of the sample is spent re-covering ground earlier draws
already covered. Choose the points deliberately — stratified, or from a
low-discrepancy sequence — and the clumping goes away by construction. The error can
then fall closer to `1/n`.

This article covers the three methods ``SamplingMethod`` offers, what each is good
for, and the one requirement they all impose on your inputs.

## The requirement: a distribution must know its own quantile

A pseudo-random run asks each input for its next value. A quasi-random run does
something different: it chooses a point in the unit hypercube *first*, then hands each
input one coordinate of it and asks what value sits there.

Only an inverse transform can answer that. So every input must conform to
``ContinuousDistribution`` or ``DiscreteDistribution`` — the protocols that add
`cdf` and `quantile` to a distribution that could previously only be sampled.

```swift
var simulation = MonteCarloSimulation(iterations: 4_096, seed: 20_260_904) { inputs in
    inputs[0] * inputs[1]
}
simulation.addInput(SimulationInput(name: "price", distribution: DistributionLogNormal(3.2, 0.4)))
simulation.addInput(SimulationInput(name: "volume", distribution: DistributionTriangular(low: 800, high: 1_400, base: 1_000)))
simulation.samplingMethod = .sobol(scrambled: false)

let results = try simulation.run()
```

An input that cannot supply a quantile — one built from a bare closure, say — makes
the run throw ``SimulationError/quasiRandomUnsupported(inputName:details:)``, naming
it:

```swift
simulation.addInput(SimulationInput(name: "opaque", sampler: { Double.random(in: 0...1) }))
simulation.samplingMethod = .latinHypercube
try simulation.run()
// SimulationError.quasiRandomUnsupported(inputName: "opaque", …)
```

It throws rather than quietly reverting to pseudo-random. A reverted run returns
numbers that are individually plausible and are not the sampling scheme you asked for,
and nothing downstream can tell the difference — which is the failure mode this
library treats as unacceptable.

> Note: Overriding a distribution's sampler does **not** forfeit eligibility.
> ``DistributionNormal`` samples by Box–Muller and ``DistributionGamma`` by rejection,
> and both remain eligible, because a quasi-random run calls `quantile` directly and
> never consults the sampler.

## Latin hypercube

Cut each dimension into *n* equal strata and use every stratum exactly once, in an
independently shuffled order per dimension.

```swift
simulation.samplingMethod = .latinHypercube
simulation.seed = 20_260_904     // required
```

The guarantee is one-dimensional and worth stating precisely: **every marginal is
perfectly stratified, and nothing is claimed about joint coverage.** For a model whose
output is dominated by one or two inputs — the common case — that is most of the
available benefit for none of the complexity.

A seed is required. The stratification is deterministic but the assignment of strata to
points is a random permutation, so an unseeded design would be reproducible in its
coverage and not in its values. That is a partial determinism which reads as
reproducible and is not, so ``MonteCarloSimulation`` refuses it.

### It composes with correlation for free

``MonteCarloSimulation``'s correlated path uses Iman–Conover: draw each marginal
independently, sort, then reorder by correlated ranks. Reordering permutes a marginal
sample without changing which values it contains — so a stratified marginal is still
stratified afterwards. Latin hypercube and rank correlation are the standard pairing
for exactly this reason.

## Sobol

A low-discrepancy sequence with a much stronger property than "evenly spread". Sobol
points form a `(t, m, s)`-net in base 2: for a prefix whose length is a power of two,
every dyadic box of the right shape holds exactly the right number of points.

```swift
simulation.samplingMethod = .sobol(scrambled: false)
```

Use a power of two for the iteration count. Other counts are a prefix of a longer
sequence and merely well-spread; at 1,024 or 4,096 you get the balance property that
makes the method worth choosing.

### Which Sobol sequence

There is no such thing as *the* Sobol sequence. Implementations differ by their
primitive polynomials and initial direction numbers, and two that disagree produce
entirely different point sets while both being perfectly valid. A sequence whose table
is unstated cannot be checked against anything, which defeats the purpose of using one.

``SobolSequence`` uses Joe & Kuo's `new-joe-kuo-6.21201`, vendored as generated source
from the same table `scipy.stats.qmc.Sobol` uses. The two libraries therefore produce
identical points, and the test suite asserts it against a fixture rather than assuming
it. The vendored table covers 256 dimensions; beyond that the initializer throws rather
than silently reducing the dimension.

### Scrambling

A plain Sobol sequence is deterministic, which costs two things: a simulation gives the
identical answer every run with no way to estimate its own error, and the sequence's
regular structure can align with a periodicity in your model.

```swift
simulation.samplingMethod = .sobol(scrambled: true)
simulation.seed = 20_260_904     // required when scrambled
```

Owen scrambling permutes the digits of each coordinate — *nested*, so the permutation
applied to a digit depends on every digit above it. That nesting is what preserves the
equidistribution: a scrambled Sobol sequence is still a Sobol sequence, with the same
balance property, and now unbiased in expectation.

## Halton

The simplest construction: write the index in base *b* and reflect its digits about the
point. Dimension *k* uses the *k*-th prime.

```swift
simulation.samplingMethod = .halton(scrambled: false)
```

### Its weakness, stated plainly

**Unscrambled Halton correlates badly between high dimensions.** For large primes the
sequence needs many points before its digits begin to cycle, so two high dimensions
march up their ranges almost in step — a scatter plot of dimension 30 against 31 shows
stripes rather than a cloud. The test suite measures that correlation rather than
avoiding it, so the limitation stays visible.

Pass `scrambled: true` to break the striping, or prefer Sobol beyond a handful of
dimensions. Halton earns its place for low-dimensional problems, where it is simple and
needs no vendored table.

## Choosing

| Method | Use it when |
|---|---|
| ``SamplingMethod/pseudoRandom`` | The default. Any number of iterations, any input, GPU eligible. |
| ``SamplingMethod/latinHypercube`` | A few inputs dominate the output. The cheapest real improvement. |
| ``SamplingMethod/sobol(scrambled:)`` | Many dimensions, iteration count a power of two, reproducibility against other tools matters. |
| ``SamplingMethod/halton(scrambled:)`` | Low dimensions, and you want a sequence with no vendored data behind it. |

## What quasi-random runs give up

**The GPU.** The Metal kernels generate their randomness on-device and have no way to
consume a host-supplied point set, so a quasi-random run executes on the CPU. The
reason is recorded in ``SimulationResults/executionNotes`` rather than left for you to
infer from the timing.

**An error estimate.** A single scrambled run is unbiased but does not report its own
uncertainty; that needs several independent scrambles, which is not yet offered.

## Sampling directly

The point sets are public and independently useful — for a design of experiments, or a
quadrature, or anything else that wants well-spread points without a simulation around
it.

```swift
let design = LatinHypercubeSampler(dimension: 3, seed: 42)
let points = design.points(count: 500)

let sobol = try SobolSequence(dimension: 8)
let grid = sobol.points(count: 1_024)
```

Every coordinate is strictly inside `(0, 1)`. That is deliberate: these points are fed
to quantile functions, and a coordinate of exactly 0 or 1 is an infinity for any
unbounded support.
