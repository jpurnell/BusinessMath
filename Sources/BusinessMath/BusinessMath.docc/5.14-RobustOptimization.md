# Robust Optimization

**Worst-case optimization** with guaranteed performance bounds under parameter uncertainty using box, ellipsoidal, and discrete uncertainty sets.

---

## Overview

This module adds **robust optimization** to BusinessMath, enabling optimization under parameter uncertainty. Unlike stochastic optimization which optimizes expected performance, robust optimization focuses on worst-case guarantees, ensuring solutions perform acceptably even when parameters take their most adverse values.

## What's Included

### 1. RobustOptimizer (304 lines)
**File:** `Sources/BusinessMath/AdvancedOptimization/RobustOptimizer.swift`

**Core Capability:**
- Solves min-max optimization problems
- Finds worst-case parameter realizations
- Supports multiple uncertainty set types
- Provides both worst-case and nominal performance metrics

**Mathematical Formulation:**
```
minimize: max{ω ∈ U} f(x, ω)

subject to:
  - g(x, ω) ≤ 0 for all ω ∈ U
  - x ∈ X (decision variable constraints)
```

Where:
- `x` is the decision vector
- `ω` represents uncertain parameters (e.g., returns, demand)
- `U` is the uncertainty set
- `f(x, ω)` is the objective depending on both decisions and parameters

**API:**
```swift
import BusinessMath

let optimizer = RobustOptimizer<VectorN<Double>>(
    uncertaintySet: try BoxUncertaintySet(
        nominal: [0.10, 0.12, 0.08],
        deviations: [0.02, 0.03, 0.01]
    ),
    samplesPerIteration: 8,  // the 8 corners of a 3-dimensional box
    maxIterations: 500,
    tolerance: 1e-6
)

let result = try optimizer.optimize(
    objective: { weights, returns in
        // Negative for maximization, less a small concentration penalty
        -(weights.dot(VectorN(returns)) - 0.05 * weights.dot(weights))
    },
    nominalParameters: [0.10, 0.12, 0.08],
    initialSolution: VectorN([0.33, 0.33, 0.34]),
    constraints: [.budgetConstraint]
        + MultivariateConstraint<VectorN<Double>>.nonNegativity(dimension: 3),
    minimize: true  // Minimize worst-case
)
```

`nonNegativity(dimension:)` returns an *array* of constraints, so it is appended
to the budget constraint rather than listed alongside it.

Two choices in that call are deliberate, and every example in this article repeats
them:

- **`samplesPerIteration: 8`.** A box uncertainty set *always* emits all 2^d of its
  corners (for d ≤ 10) before it draws anything at random, so 8 is the smallest
  honest request for three uncertain parameters. When the objective is linear in the
  parameters — as a portfolio return is — its maximum over the box is attained at a
  corner, so interior samples cost time without ever changing the answer. Asking for
  100 samples here adds 92 random interior points that are all strictly dominated.
  Interior samples earn their keep only when the objective is *nonlinear* in ω.
- **The `0.05 * weights.dot(weights)` term.** A worst-case objective that is purely
  linear in the weights is the slow case for this solver: the inner BFGS loop inside
  the augmented Lagrangian tests an *absolute* gradient tolerance that a penalised
  objective scaled by ρ never reaches, so it spends its full inner iteration budget
  on every outer iteration. Any strictly convex term — a variance penalty, or this
  concentration penalty — makes the same problem converge roughly a hundred times
  faster. See **Performance Characteristics**, below.

**Three Implementations:**

#### A. Box Uncertainty Set
Rectangular uncertainty: `ω ∈ [ω̄ - δ, ω̄ + δ]`

```swift
let box = try BoxUncertaintySet(
    nominal: [0.10, 0.12, 0.08],
    deviations: [0.02, 0.03, 0.01]  // ±2%, ±3%, ±1%
)

// Returns range from [0.08, 0.09, 0.07] to [0.12, 0.15, 0.09]
```

**Properties:**
- Simple to specify and interpret
- Conservative (considers worst corners)
- Includes all 2^d corner points in sampling

#### B. Ellipsoidal Uncertainty Set
Elliptical uncertainty: `||Σ^(-1/2)(ω - ω̄)|| ≤ κ`

```swift
let ellipsoidCovariance: [[Double]] = [
    [0.0400, 0.0120, 0.0080],
    [0.0120, 0.0225, 0.0090],
    [0.0080, 0.0090, 0.0100]
]

let ellipsoid = try EllipsoidalUncertaintySet(
    nominal: [0.10, 0.12, 0.08],
    covariance: ellipsoidCovariance,
    radius: 2.0  // 2-sigma ellipsoid
)
```

**Properties:**
- Based on statistical covariance
- Less conservative than box for correlated parameters
- Natural for financial applications

#### C. Discrete Uncertainty Set
Finite scenarios: `ω ∈ {ω₁, ω₂, ..., ωₙ}`

```swift
let discrete = try DiscreteUncertaintySet(
    points: [
        [0.05, 0.08, 0.03],  // Bear market
        [0.10, 0.12, 0.08],  // Normal market
        [0.15, 0.18, 0.12]   // Bull market
    ]
)
```

**Properties:**
- Explicit scenario definition
- Exact worst-case evaluation (no sampling)
- Useful for stress testing

## Usage Examples

### Example 1: Worst-Case Portfolio Optimization with Risk Constraints

**Problem:** Maximize worst-case portfolio return when asset returns are uncertain, subject to concentration limits and variance penalties.

```swift
import BusinessMath

// Nominal expected returns and their uncertainty
let nominalReturns_worstCasePortfolio = [0.10, 0.12, 0.08]  // Tech, Healthcare, Utilities
let deviations_worstCasePortfolio = [0.03, 0.02, 0.01]      // ±3%, ±2%, ±1%

// Asset volatilities (for risk penalty)
let volatilities_worstCasePortfolio = [0.15, 0.10, 0.05]

// Risk aversion parameter (balances worst-case return vs variance)
let riskAversion_worstCasePortfolio = 1.5

// Build covariance matrix (simplified: diagonal)
let covarianceMatrix_worstCasePortfolio = (0..<3).map { i in
	(0..<3).map { j in
		i == j ? volatilities_worstCasePortfolio[i] * volatilities_worstCasePortfolio[i] : 0.0
	}
}

// Create uncertainty set
let uncertaintySet_worstCasePortfolio = try BoxUncertaintySet(
	nominal: nominalReturns_worstCasePortfolio,
	deviations: deviations_worstCasePortfolio
)

// Create robust optimizer
let optimizer_worstCasePortfolio = RobustOptimizer<VectorN<Double>>(
	uncertaintySet: uncertaintySet_worstCasePortfolio,
	samplesPerIteration: 8,  // the 8 corners of the box — see "API", above
	maxIterations: 500,
	tolerance: 1e-6
)

// Build constraints
var constraints_worstCasePortfolio: [MultivariateConstraint<VectorN<Double>>] = [
	.budgetConstraint  // Σw = 1
]
constraints_worstCasePortfolio.append(contentsOf:
	MultivariateConstraint<VectorN<Double>>.nonNegativity(dimension: 3)
)

// Add concentration limits (max 40% in any single asset for diversification)
for i in 0..<3 {
	constraints_worstCasePortfolio.append(
		.inequality(
			function: { weights in
				weights.toArray()[i] - 0.40  // asset[i] ≤ 40%
			},
			gradient: nil
		)
	)
}

// Optimize for worst-case with risk penalty
let result_worstCasePortfolio = try optimizer_worstCasePortfolio.optimize(
	objective: { weights, returns in
		let w = weights.toArray()

		// Expected return under this scenario
		let expectedReturn = weights.dot(VectorN(returns))

		// Portfolio variance: w^T Σ w
		let variance = (0..<3).map { i in
			(0..<3).map { j in
				w[i] * covarianceMatrix_worstCasePortfolio[i][j] * w[j]
			}.reduce(0, +)
		}.reduce(0, +)

		// Minimize negative risk-adjusted return (= maximize risk-adjusted return)
		return -(expectedReturn - riskAversion_worstCasePortfolio * variance)
	},
	nominalParameters: nominalReturns_worstCasePortfolio,
	initialSolution: VectorN([0.33, 0.33, 0.34]),
	constraints: constraints_worstCasePortfolio,
	minimize: true  // Minimize worst-case (= maximize worst-case risk-adjusted return)
)

// Analyze results
print("Robust portfolio optimization complete!")
print("Converged: \(result_worstCasePortfolio.converged)")
print()

let weights_worstCasePortfolio = result_worstCasePortfolio.solution.toArray()
print("Optimal weights:")
for (i, w) in weights_worstCasePortfolio.enumerated() {
	print("  Asset \(i+1): \(w.percent(1))")
}
print()

print("Performance metrics:")
print("  Worst-case return: \((-1.0 * result_worstCasePortfolio.worstCaseObjective).percent(2))")
print("  Nominal return: \((-1.0 * result_worstCasePortfolio.nominalObjective).percent(2))")
print("  Downside protection: \(((-1.0 * result_worstCasePortfolio.nominalObjective) + result_worstCasePortfolio.worstCaseObjective).percent(2))")
print()

print("Worst-case scenario:")
for (i, r) in result_worstCasePortfolio.worstCaseParameters.enumerated() {
	print("  Asset \(i+1) return: \(r.percent(2))")
}
```

**Expected Output:**
```
Robust portfolio optimization complete!
Converged: true

Optimal weights:
  Asset 1: 20.0%
  Asset 2: 40.0%
  Asset 3: 40.0%

Performance metrics:
  Worst-case return: 7.77%
  Nominal return: 9.57%
  Downside protection: 1.80%

Worst-case scenario:
  Asset 1 return: 7.00%
  Asset 2 return: 10.00%
  Asset 3 return: 7.00%
```

**Key Insights:**
- **Healthcare (40%):** Pinned at the concentration cap — the best balance of return (12%), uncertainty (±2%) and volatility (10%)
- **Utilities (40%):** Also pinned at the cap, on the strength of the smallest uncertainty (±1%) and the lowest volatility (5%), despite the lowest nominal return (8%)
- **Tech (20%):** Gets only what the caps leave over. Its 10% nominal return is respectable, but ±3% uncertainty and 15% volatility are penalised twice
- **Worst-case scenario:** every asset at its lower bound, because a portfolio return is linear in the returns — the maximum over the box is always a corner

**★ Insight ─────────────────────────────────────**
Why does robust optimization favor low-volatility assets so heavily?

1. **Dual Risk Penalties:** The objective combines worst-case protection (via robust optimization) with variance penalties (via mean-variance term). Assets face TWO sources of risk penalization.

2. **Concentration Limits Bind:** Both Healthcare and Utilities sit exactly on the 40% cap; the cap is the only reason Tech is held at all. Raise it to 50% and the answer moves to roughly 5% / 50% / 45% — the optimizer crowds into the two low-uncertainty assets and nearly abandons Tech.

3. **Worst-Case Variance Matters:** The optimizer considers variance in EVERY scenario, not just the nominal. Volatility is penalised even when an asset's worst-case return is good.

The gap between the nominal return (9.57%) and the worst-case return (7.77%) is the downside this portfolio is built to absorb: 1.80 percentage points.
**─────────────────────────────────────────────────**

### Example 2: The Price of Robustness Across Explicit Scenarios

**Problem:** Understand what robustness costs, by comparing a portfolio built on a
single point estimate with one built to survive every scenario on the table.

Three named scenarios are the exact case for robust optimization: a
``DiscreteUncertaintySet`` evaluates the worst case over the scenarios themselves,
with no sampling and no approximation, so the answer is reproducible to the last
digit.

```swift
let nominalReturns = [0.10, 0.12, 0.08]  // the "normal market" scenario

let marketScenarios = [
    [0.15, 0.18, 0.12],  // Bull market
    [0.10, 0.12, 0.08],  // Normal market (nominal)
    [0.08, 0.06, 0.07]   // Bear market
]
let scenarioNames = ["Bull", "Normal", "Bear"]

var constraints: [MultivariateConstraint<VectorN<Double>>] = [.budgetConstraint]
constraints.append(contentsOf:
    MultivariateConstraint<VectorN<Double>>.nonNegativity(dimension: 3)
)

// A weight can land a few 1e-7 outside its constraint — that is the optimizer's
// 1e-6 constraint tolerance, not a negative holding. Round before displaying.
func percentString(_ weight: Double) -> String {
    let rounded = (weight * 1000).rounded() / 10
    return String(format: "%.1f%%", rounded == 0 ? 0 : rounded)
}

// APPROACH 1: Nominal optimization (ignores uncertainty)
print("=== NOMINAL OPTIMIZATION ===")
let nominalOptimizer = InequalityOptimizer<VectorN<Double>>(
    constraintTolerance: 1e-6,
    gradientTolerance: 1e-6,
    maxIterations: 500
)

let nominalResult = try nominalOptimizer.minimize(
    { weights in
        -weights.dot(VectorN(nominalReturns))  // Maximize expected return
    },
    from: VectorN([0.33, 0.33, 0.34]),
    subjectTo: constraints
)

let nominalWeights = nominalResult.solution.toArray()
print("Optimal weights: \(nominalWeights.map(percentString))")
let nominalExpectedReturn = nominalResult.solution.dot(VectorN(nominalReturns))
print("Expected return: \(String(format: "%.2f%%", nominalExpectedReturn * 100))")

// What the nominal solution earns if the bear scenario is the one that happens
let bearReturns = marketScenarios[2]
let nominalWorstCase = nominalResult.solution.dot(VectorN(bearReturns))
print("Worst-case return: \(String(format: "%.2f%%", nominalWorstCase * 100))")
print()

// APPROACH 2: Robust optimization (protects against the worst scenario)
print("=== ROBUST OPTIMIZATION ===")
let robustResult = try RobustOptimizer<VectorN<Double>>.optimizeDiscrete(
    objective: { weights, returns in -weights.dot(VectorN(returns)) },
    uncertainPoints: marketScenarios,
    nominalIndex: 1,  // Normal market is nominal
    initialSolution: VectorN([0.33, 0.33, 0.34]),
    constraints: constraints,
    minimize: true
)

let robustWeights = robustResult.solution.toArray()
print("Optimal weights: \(robustWeights.map(percentString))")
print("Expected return: \(String(format: "%.2f%%", -robustResult.nominalObjective * 100))")
print("Worst-case return: \(String(format: "%.2f%%", -robustResult.worstCaseObjective * 100))")
print()

// Evaluate the robust portfolio in every scenario
print("Performance across scenarios:")
for (i, scenario) in marketScenarios.enumerated() {
    let scenarioReturn = robustResult.solution.dot(VectorN(scenario))
    print("  \(scenarioNames[i]): \(String(format: "%.2f%%", scenarioReturn * 100))")
}

let worstScenarioIndex = marketScenarios.indices.min {
    robustResult.solution.dot(VectorN(marketScenarios[$0]))
        < robustResult.solution.dot(VectorN(marketScenarios[$1]))
}!
print("Binding scenario: \(scenarioNames[worstScenarioIndex])")
print()

// COMPARISON
print("=== COMPARISON ===")
let expectedReturnLoss = nominalExpectedReturn - (-robustResult.nominalObjective)
let worstCaseGain = -robustResult.worstCaseObjective - nominalWorstCase
print("Expected return sacrifice: \(String(format: "%.2f%%", expectedReturnLoss * 100))")
print("Worst-case return improvement: \(String(format: "%.2f%%", worstCaseGain * 100))")
print("Trade-off ratio: \(String(format: "%.2f", worstCaseGain / expectedReturnLoss))")
```

**Expected Output:**
```
=== NOMINAL OPTIMIZATION ===
Optimal weights: ["0.0%", "100.0%", "0.0%"]
Expected return: 12.00%
Worst-case return: 6.00%

=== ROBUST OPTIMIZATION ===
Optimal weights: ["100.0%", "0.0%", "0.0%"]
Expected return: 10.00%
Worst-case return: 8.00%

Performance across scenarios:
  Bull: 15.00%
  Normal: 10.00%
  Bear: 8.00%
Binding scenario: Bear

=== COMPARISON ===
Expected return sacrifice: 2.00%
Worst-case return improvement: 2.00%
Trade-off ratio: 1.00
```

**Interpretation:** The nominal optimizer reads the normal-market column, sees that
Healthcare pays the most, and buys nothing else — a 12% expected return that becomes
6% if the bear scenario arrives. The robust optimizer reads *down* to the bear row,
where Healthcare is the worst of the three, and buys Tech instead. It gives up 2
percentage points of expected return to gain 2 points of worst-case return: a
trade-off ratio of 1.00.

Notice that neither answer diversifies. With an objective that is linear in the
weights, the optimum of both problems is a single asset; what changes is *which*
column decides it. Diversification appears only when something curves the objective
— the variance penalty and concentration caps of Example 1, or a scenario set in
which no single asset is best in the binding scenario.

### Example 3: Robust Production Planning Under Demand Uncertainty

**Problem:** Determine production quantity when demand is uncertain.

This is the `optimizeBox` convenience method, on the smallest robust problem there
is: one decision variable, one uncertain parameter, and therefore a box with exactly
two corners.

```swift
// Production parameters
let productionCost = 10.0     // Cost per unit
let sellingPrice = 25.0       // Revenue per unit sold
let shortagePenalty = 5.0     // Penalty per unit of unmet demand
let excessPenalty = 2.0       // Holding cost for unsold units

// Uncertain demand: nominal 100 units, can vary ±20
let nominalDemand = [100.0]
let demandDeviation = [20.0]

// Create optimizer
let productionResult = try RobustOptimizer<VectorN<Double>>.optimizeBox(
    objective: { production, demand in
        let q = production.toArray()[0]
        let d = max(0, demand[0])

        // Revenue from units sold
        let revenue = min(q, d) * sellingPrice

        // Production cost
        let cost = q * productionCost

        // Shortage penalty (unmet demand)
        let shortageCost = max(0, d - q) * shortagePenalty

        // Excess holding cost (unsold inventory)
        let excessCost = max(0, q - d) * excessPenalty

        // Total profit (negative for maximization)
        return -(revenue - cost - shortageCost - excessCost)
    },
    nominal: nominalDemand,
    deviations: demandDeviation,
    initialSolution: VectorN([100.0]),
    constraints: [
        .inequality(
            function: { x in -x.toArray()[0] },  // q >= 0
            gradient: nil
        ),
        .inequality(
            function: { x in x.toArray()[0] - 150.0 },  // q <= 150
            gradient: nil
        )
    ],
    minimize: true,
    samplesPerIteration: 2  // both ends of a 1-dimensional box
)

print("Robust Production Planning")
print("==========================")
print()

let optimalProduction = productionResult.solution.toArray()[0]
print("Optimal production quantity: \(Int(optimalProduction)) units")
print()

// Evaluate scenarios
let demandScenarios = [
    ("Low demand (80)", 80.0),
    ("Nominal demand (100)", 100.0),
    ("High demand (120)", 120.0)
]

print("Profit under different demand scenarios:")
for (name, demand) in demandScenarios {
    let q = optimalProduction
    let revenue = min(q, demand) * sellingPrice
    let cost = q * productionCost
    let shortage = max(0, demand - q) * shortagePenalty
    let excess = max(0, q - demand) * excessPenalty
    let profit = revenue - cost - shortage - excess

    print("  \(name): $\(String(format: "%.2f", profit))")
}
print()

print("Worst-case profit: $\(String(format: "%.2f", -productionResult.worstCaseObjective))")
print("Nominal profit: $\(String(format: "%.2f", -productionResult.nominalObjective))")
```

**Expected Output:**
```
Robust Production Planning
==========================

Optimal production quantity: 86 units

Profit under different demand scenarios:
  Low demand (80): $1125.00
  Nominal demand (100): $1225.00
  High demand (120): $1125.00

Worst-case profit: $1125.00
Nominal profit: $1225.00
```

**Interpretation:** The robust quantity is *below* nominal demand — 86 units against
a nominal 100 — and the reason is visible in the output: the two ends of the demand
range yield exactly the same profit, $1125.00. That is the signature of a worst-case
optimum. Producing one more unit gains $27 of margin-plus-avoided-shortage if demand
turns out high, and costs $12 of production-plus-holding if it turns out low, so the
optimizer moves q until the low-demand and high-demand profits meet:
27·80 − 12·q = 20·q − 5·120 gives q = 86.25. Anything above that hands the low-demand
case a loss it cannot recover, and the worst case is all this objective is scored on.

Note what robustness costs here. Simply producing to nominal demand — 100 units —
earns $1500.00 if demand is exactly 100, but only $960.00 if it comes in at 80. The
robust plan gives up $275.00 of that nominal profit to raise the floor by $165.00.

### Example 4: Ellipsoidal Uncertainty with Correlated Returns

**Problem:** Use statistical covariance structure to define uncertainty, and see how
much less conservative it is than a box of the same nominal size.

This example scores a fixed portfolio against both sets rather than optimizing over
the ellipsoid, and that is a deliberate choice worth explaining.
``EllipsoidalUncertaintySet`` draws its sample points with an unseeded
`Double.random`, and the library exposes no way to seed it, so two runs of the same
ellipsoidal *optimization* return different weights and a different worst case. A
worked example whose numbers change every time it is run teaches nothing, so the
comparison below is done in closed form — which, for an objective linear in the
parameters, is exact anyway.

```swift
// Three assets with correlated returns
let correlatedReturns = [0.10, 0.12, 0.08]

// Historical covariance matrix (from data).
// Named `historicalCovariance` rather than `covariance` so it does not shadow
// BusinessMath's `covariance(_:_:_:)` function.
let historicalCovariance: [[Double]] = [
    [0.0400, 0.0120, 0.0080],  // Tech: high volatility
    [0.0120, 0.0225, 0.0090],  // Finance: correlated with tech
    [0.0080, 0.0090, 0.0100]   // Utilities: lower volatility
]

// 2-sigma ellipsoid (covers ~95% of historical variation)
let uncertaintySet = try EllipsoidalUncertaintySet(
    nominal: correlatedReturns,
    covariance: historicalCovariance,
    radius: 2.0
)

// The box of the same nominal size: ±2σ on each asset, independently
let standardDeviations = (0..<historicalCovariance.count).map {
    sqrt(historicalCovariance[$0][$0])
}
let matchingBox = try BoxUncertaintySet(
    nominal: correlatedReturns,
    deviations: standardDeviations.map { $0 * 2.0 }
)

// Score the same equally weighted portfolio against both sets
let equalWeights = [1.0 / 3.0, 1.0 / 3.0, 1.0 / 3.0]
let equalWeightReturn = zip(equalWeights, correlatedReturns).map(*).reduce(0, +)

// Box worst case: every asset at its lower bound at once
let boxWorstCase = zip(equalWeights, matchingBox.lowerBounds).map(*).reduce(0, +)

// Ellipsoid worst case: w·μ − κ·√(wᵀΣw), exact for a linear objective
let portfolioVariance = (0..<3).map { i in
    (0..<3).map { j in
        equalWeights[i] * historicalCovariance[i][j] * equalWeights[j]
    }.reduce(0, +)
}.reduce(0, +)
let ellipsoidWorstCase = equalWeightReturn - 2.0 * sqrt(portfolioVariance)

print("Box vs ellipsoid, same portfolio")
print("================================")
print()
print("Expected return: \(String(format: "%.2f%%", equalWeightReturn * 100))")
print("Box worst case (±2σ each): \(String(format: "%.2f%%", boxWorstCase * 100))")
print("Ellipsoid worst case (2σ): \(String(format: "%.2f%%", ellipsoidWorstCase * 100))")
print("Ellipsoid less conservative by: \(String(format: "%.2f%%", (ellipsoidWorstCase - boxWorstCase) * 100))")
print()

// The box's worst corner is a scenario the ellipsoid rules out entirely
let boxWorstCorner = matchingBox.lowerBounds
print("Box worst corner: \(boxWorstCorner.map { String(format: "%.2f", $0) })")
print("  in the box?       \(matchingBox.contains(boxWorstCorner))")
print("  in the ellipsoid? \(uncertaintySet.contains(boxWorstCorner))")
```

**Expected Output:**
```
Box vs ellipsoid, same portfolio
================================

Expected return: 10.00%
Box worst case (±2σ each): -20.00%
Ellipsoid worst case (2σ): -14.08%
Ellipsoid less conservative by: 5.92%

Box worst corner: ["-0.30", "-0.18", "-0.12"]
  in the box?       true
  in the ellipsoid? false
```

**Interpretation:** The box asks the portfolio to survive all three assets falling
2σ *simultaneously*, a scenario 3.46σ away from nominal in Mahalanobis distance —
which is why the ellipsoid reports it as outside the set. The ellipsoid asks only
that the portfolio survive any single realization within 2σ of nominal once
correlations are accounted for, and charges 5.92 percentage points less for it.

That gap is the price of ignoring correlation structure, and it grows with dimension:
a box over d assets always contains a corner at √d σ, while the ellipsoid stops at κσ
regardless of d.

## Key Concepts

### 1. Robust Counterpart Formulation

Original uncertain problem:
```
maximize f(x, ω)  where ω is uncertain
```

Robust counterpart:
```
maximize min{ω ∈ U} f(x, ω)
```

Or equivalently (for minimization):
```
minimize max{ω ∈ U} f(x, ω)
```

**Key insight:** Instead of optimizing expected or probable performance, we optimize the worst case.

### 2. Uncertainty Sets

#### Box Uncertainty
```
U = {ω : ωᵢ ∈ [ω̄ᵢ - δᵢ, ω̄ᵢ + δᵢ] for all i}
```

**Properties:**
- Simple to specify (one deviation per parameter)
- Rectangular shape in parameter space
- Conservative (considers extreme corners)
- 2^d corner points for d-dimensional parameters

**When to use:**
- Simple bounds are known
- Conservative protection desired
- No correlation structure available

#### Ellipsoidal Uncertainty
```
U = {ω : (ω - ω̄)ᵀΣ⁻¹(ω - ω̄) ≤ κ²}
```

**Properties:**
- Based on covariance matrix Σ
- Captures parameter correlations
- Statistically motivated (e.g., 2σ ellipsoid)
- Less conservative than box for correlated parameters

**When to use:**
- Historical covariance data available
- Parameters are correlated
- Statistical confidence regions desired

#### Discrete Uncertainty
```
U = {ω₁, ω₂, ..., ωₙ}
```

**Properties:**
- Finite set of explicit scenarios
- Exact worst-case evaluation
- Natural for stress testing
- Easy to interpret and communicate

**When to use:**
- Expert scenarios available
- Stress testing specific conditions
- Small number of relevant cases
- Regulatory scenarios

### 3. Price of Robustness

The **price of robustness** is the performance sacrifice at nominal parameters to gain worst-case protection.

```
Price = NominalObjective(robust) - NominalObjective(nominal)
Gain = WorstCase(robust) - WorstCase(nominal)
```

**Example** — these are the figures Example 2 actually prints:
- Nominal optimization: 12% expected, 6% worst-case
- Robust optimization: 10% expected, 8% worst-case
- Price: -2% expected return
- Gain: +2% worst-case protection
- Trade-off ratio: 1.0 (equal trade-off)

### 4. Conservatism Levels

Control conservatism through uncertainty set size:

```swift
let returns = [0.10, 0.12, 0.08]
let cov: [[Double]] = [
    [0.0400, 0.0120, 0.0080],
    [0.0120, 0.0225, 0.0090],
    [0.0080, 0.0090, 0.0100]
]

// More conservative (larger uncertainty)
let wideBox = try BoxUncertaintySet(nominal: returns, deviations: returns.map { $0 * 0.30 })  // ±30%

// Less conservative (smaller uncertainty)
let tightBox = try BoxUncertaintySet(nominal: returns, deviations: returns.map { $0 * 0.10 })  // ±10%

// Very conservative (3-sigma)
let threeSigmaEllipsoid = try EllipsoidalUncertaintySet(nominal: returns, covariance: cov, radius: 3.0)

// Moderate (2-sigma, ~95% coverage)
let twoSigmaEllipsoid = try EllipsoidalUncertaintySet(nominal: returns, covariance: cov, radius: 2.0)
```

### 5. Robust vs Stochastic Optimization

| Aspect | Robust | Stochastic |
|--------|--------|------------|
| **Objective** | Worst-case | Expected value |
| **Philosophy** | Pessimistic | Neutral/Optimistic |
| **Protection** | Guaranteed bounds | Probabilistic |
| **Conservatism** | More conservative | Less conservative |
| **Risk metric** | Worst-case | Variance/CVaR |
| **Data requirement** | Bounds/scenarios | Probability distribution |

**When to use robust:**
- Worst-case guarantees critical
- Conservative protection desired
- Limited statistical confidence
- Regulatory requirements
- High-stakes decisions

**When to use stochastic:**
- Expected performance matters most
- Rare events acceptable
- Good probabilistic models available
- Risk-neutral preference
- Frequent repeated decisions

## Algorithm Details

### Sampling-Based Approach

The implementation uses sampling to approximate the worst-case:

1. **Sample Generation:** Generate N sample points from uncertainty set U
2. **Worst-Case Evaluation:** For each candidate solution x, evaluate f(x, ω) at all samples
3. **Worst-Case Objective:** Define robust objective as maximum over samples
4. **Optimization:** Use constrained optimizer to minimize worst-case objective

**Pseudocode:**
```
function robustOptimize(f, U, constraints):
    samples = U.samplePoints(N)

    function worstCaseObjective(x):
        worstValue = -infinity
        for ω in samples:
            value = f(x, ω)
            worstValue = max(worstValue, value)
        return worstValue

    return constrainedOptimizer.minimize(
        worstCaseObjective,
        constraints
    )
```

### Sampling Strategies

**Box Uncertainty:**
- Include all 2^d corners (for d ≤ 10)
- Add random uniform samples from box interior
- Ensures extreme cases are considered

**Ellipsoidal Uncertainty:**
- Random samples from ellipsoid surface
- Scaled by covariance matrix
- Approximately uniform angular distribution

**Discrete Uncertainty:**
- Return all discrete points (exact)
- No approximation needed

### Computational Complexity

One objective evaluation costs O(N × d) — it walks every sample. The optimizer then
multiplies that by everything above it:

```
objective evaluations ≈ outerIterations × innerIterations × (2d + 1) × lineSearchSteps
```

The `2d + 1` is the numerical gradient: there are no analytic derivatives here, so
each BFGS step re-evaluates the whole worst-case objective twice per dimension. With
`N` samples on top, the sample count is a multiplier on *everything*, which is why
Example 1 asks for 8 samples rather than 100.

**Space Complexity:** O(N × d) — all sample points are held for the whole solve.

**Convergence:** Depends on:
- Sample size (more samples → better approximation)
- Constraint tightness
- Initial guess quality
- Problem conditioning

### Accuracy vs Speed Trade-off

```swift
// A box emits all 2^d corners regardless; this is the floor for 3 parameters
let cornersOnlySamples = 8

// Interior samples, for an objective that is nonlinear in the parameters
let interiorSearchSamples = 100

// A wide interior search — rarely worth it, and it multiplies every evaluation
let exhaustiveSamples = 500
```

For discrete uncertainty, use exact number of scenarios (no approximation).

## Best Practices

### 1. Choose Appropriate Uncertainty Set

**Start with box uncertainty** for simplicity:
```swift
// Simple ±20% bounds
let simpleBoundsDeviations = nominalReturns.map { abs($0) * 0.20 }
```

**Upgrade to ellipsoidal** when correlations matter:
```swift
// Use historical covariance, built from BusinessMath's covariance(_:_:_:)
let historicalReturns: [[Double]] = [
    [0.11, 0.08, 0.14, 0.07, 0.10],  // Tech
    [0.13, 0.10, 0.15, 0.09, 0.12],  // Finance
    [0.08, 0.07, 0.09, 0.08, 0.08]   // Utilities
]

func estimateCovariance(_ series: [[Double]]) -> [[Double]] {
    series.map { row in series.map { covariance(row, $0) } }
}

let expectedReturns = historicalReturns.map { $0.reduce(0, +) / Double($0.count) }
let estimatedCovariance = estimateCovariance(historicalReturns)

let historicalUncertaintySet = try EllipsoidalUncertaintySet(
    nominal: expectedReturns,
    covariance: estimatedCovariance,
    radius: 2.0  // 2-sigma
)
```

**Use discrete** for specific scenarios:
```swift
// Expert scenarios or regulatory stress tests
let baseCase = [0.10, 0.12, 0.08]
let recession = [0.02, 0.04, 0.05]
let crisis = [-0.15, -0.10, 0.01]
let boom = [0.18, 0.20, 0.11]

let expertScenarios = [baseCase, recession, crisis, boom]
```

### 2. Calibrate Uncertainty Set Size

Start conservative, then relax:

```swift
// Step 1: Very conservative (see if feasible)
let step1Deviations = nominalReturns.map { abs($0) * 0.50 }  // ±50%

// Step 2: Moderate (realistic)
let step2Deviations = nominalReturns.map { abs($0) * 0.20 }  // ±20%

// Step 3: Optimistic (if too conservative)
let step3Deviations = nominalReturns.map { abs($0) * 0.10 }  // ±10%
```

### 3. Validate Worst-Case Realization

Always inspect the worst-case parameters. They come back on every ``RobustResult``,
so this costs nothing — there is no need to re-solve. Here is the box result from
Example 1:

```swift
print("Worst-case parameters:")
for (i, param) in result_worstCasePortfolio.worstCaseParameters.enumerated() {
    let nominalValue = nominalReturns_worstCasePortfolio[i]
    let deviation = param - nominalValue
    print("  Param \(i): \(String(format: "%.4f", param))"
        + " (nominal: \(String(format: "%.4f", nominalValue)),"
        + " deviation: \(String(format: "%+.4f", deviation)))")
}

// Verify they're in the uncertainty set
assert(uncertaintySet_worstCasePortfolio.contains(result_worstCasePortfolio.worstCaseParameters))
```

**Expected Output:**
```
Worst-case parameters:
  Param 0: 0.0700 (nominal: 0.1000, deviation: -0.0300)
  Param 1: 0.1000 (nominal: 0.1200, deviation: -0.0200)
  Param 2: 0.0700 (nominal: 0.0800, deviation: -0.0100)
```

Every parameter sits exactly on its lower bound. For an objective linear in the
parameters that is the expected answer, and seeing anything else — a worst case in
the interior of the box — is a signal that the objective is not what you thought it
was.

### 4. Compare with Nominal Solution

Quantify the price of robustness. Both solutions are already in hand from Example 2,
so this is arithmetic rather than a third and fourth solve:

```swift
let stressReturns = marketScenarios[2]  // the bear scenario

// Expected return of an allocation under one parameter realization
func evaluate(_ solution: VectorN<Double>, _ parameters: [Double]) -> Double {
    solution.dot(VectorN(parameters))
}

let nominalAtNominal = evaluate(nominalResult.solution, nominalReturns)
let nominalAtWorst = evaluate(nominalResult.solution, stressReturns)
let robustAtNominal = evaluate(robustResult.solution, nominalReturns)
let robustAtWorst = evaluate(robustResult.solution, stressReturns)

print("Performance comparison:")
print("  Nominal solution: \(String(format: "%.4f", nominalAtNominal)) (nominal),"
    + " \(String(format: "%.4f", nominalAtWorst)) (worst)")
print("  Robust solution: \(String(format: "%.4f", robustAtNominal)) (nominal),"
    + " \(String(format: "%.4f", robustAtWorst)) (worst)")
print("  Price of robustness: \(String(format: "%+.4f", robustAtNominal - nominalAtNominal))")
print("  Worst-case improvement: \(String(format: "%+.4f", robustAtWorst - nominalAtWorst))")
```

**Expected Output:**
```
Performance comparison:
  Nominal solution: 0.1200 (nominal), 0.0600 (worst)
  Robust solution: 0.1000 (nominal), 0.0800 (worst)
  Price of robustness: -0.0200
  Worst-case improvement: +0.0200
```

Print these with a fixed number of digits rather than raw `Double`s. The optimizer
converges to within its 1e-6 constraint tolerance, not to the bit, so raw values
carry a tail of noise that changes with the platform's floating-point library and
tells you nothing about the answer.

### 5. Choose the Sample Count to Match the Objective

The right number of samples is not a fixed number — it depends on how the objective
depends on the uncertain parameters:

```swift
// A box always emits all 2^d corners first (for d ≤ 10), so this is the floor
let cornersOfThreeDimensionalBox = 8

// Linear in ω: the worst case is always a corner. Interior samples cannot
// improve the answer, and every one of them is paid for on every evaluation.
let samplesForLinearObjective = cornersOfThreeDimensionalBox

// Nonlinear in ω: the worst case may be interior, so corners are not enough
let samplesForNonlinearObjective = 100
```

For discrete uncertainty, use all points — the evaluation is then exact.

### 6. Check Convergence and Feasibility

```swift
@MainActor func checkConvergenceAndFeasibility(_ result: RobustResult<VectorN<Double>>) {
    guard result.converged else {
        print("Warning: Did not converge!")
        print("Iterations: \(result.iterations)")
        // Consider relaxing constraints or increasing maxIterations
        return
    }

    // Verify solution is feasible
    let weights = result.solution.toArray()
    let sum = weights.reduce(0, +)
    assert(abs(sum - 1.0) < 1e-3, "Budget constraint violated")
    assert(weights.allSatisfy { $0 >= -1e-6 }, "Non-negativity violated")
    print("Converged in \(result.iterations) outer iterations; solution is feasible.")
}

checkConvergenceAndFeasibility(result_worstCasePortfolio)
```

**Expected Output:**
```
Converged in 5 outer iterations; solution is feasible.
```

## Common Pitfalls

### 1. Over-Conservative Uncertainty Sets

**Problem:** Uncertainty set too large, resulting in overly conservative solutions.

**Example:**
```swift
// TOO CONSERVATIVE: ±100% bounds
let overConservativeDeviations = nominalReturns.map { abs($0) * 1.0 }
// Result: Allocate everything to risk-free asset
```

**Solution:** Calibrate based on historical data or expert judgment (typically ±10% to ±30%).

### 2. Under-Sampling — and Over-Sampling

**Problem:** Too few samples miss the true worst-case; too many make every evaluation
more expensive without changing the answer.

**Example:**
```swift
// A box over 5 uncertain parameters has 32 corners; asking for 10 gets you
// 32 anyway, because corners are emitted first
let underSampledCount = 10

// 500 samples over 3 parameters: 8 corners and 492 interior points, none of
// which can beat a corner if the objective is linear in ω
let overSampledCount = 500
```

**Solution:** Decide from the objective, not from a rule of thumb. If it is linear
in the uncertain parameters, the corner count is both necessary and sufficient. If it
is nonlinear in them — a payoff with a `min` or a `max` in it, an option, a piecewise
cost — the worst case can be interior and interior samples are what find it.

### 3. Ignoring Correlations

**Problem:** Using box uncertainty when parameters are correlated.

**Example:**
```swift
// Tech and Finance returns are 80% correlated
// Box assumes they can vary independently (too conservative)
let independentBox = try BoxUncertaintySet(nominal: [0.10, 0.12], deviations: [0.03, 0.04])
```

**Solution:** Use ellipsoidal uncertainty with covariance matrix.

### 4. Inconsistent Nominal Parameters

**Problem:** Nominal parameters don't match uncertainty set center.

Nothing validates this for you: `optimize` takes `nominalParameters` as a separate
argument from the set, and reports `nominalObjective` at whatever you pass. If that
point is not in the set, the "nominal" figure describes a scenario the optimization
never considered — and no error is raised.

**Example:**
```swift
let mismatchedSet = try BoxUncertaintySet(
    nominal: [0.10, 0.12, 0.08],  // Center at these values
    deviations: [0.02, 0.03, 0.01]
)

// BUG: a different nominal would be passed to optimize(nominalParameters:)
let wrongNominal = [0.09, 0.11, 0.07]  // WRONG!

let centreOffset = zip(wrongNominal, mismatchedSet.nominal).map { $0 - $1 }
print("Offset from the set's centre: \(centreOffset.map { String(format: "%+.4f", $0) })")
print("Still inside the set? \(mismatchedSet.contains(wrongNominal))")
```

**Expected Output:**
```
Offset from the set's centre: ["-0.0100", "-0.0100", "-0.0100"]
Still inside the set? true
```

Note that a membership test does *not* catch this: the wrong nominal is comfortably
inside the box. It is simply not the centre, so the reported `nominalObjective`
describes a different portfolio problem than the worst case does.

**Solution:** Compare `nominalParameters` against `uncertaintySet.nominal` directly,
not against the set's bounds.

### 5. Wrong Optimization Direction

**Problem:** Confusing minimize/maximize with worst-case.

**Example:**
```swift
// Want to maximize worst-case return
// WRONG: passing this as `minimize:` maximizes the maximum return (best case!)
let wrongMinimizeFlag = false

// CORRECT: Minimize negative return = maximize return
let negatedObjective: @Sendable (VectorN<Double>, [Double]) -> Double = { weights, returns in
    -weights.dot(VectorN(returns))
}
let correctMinimizeFlag = true  // Minimize worst-case of negative = maximize worst-case return
```

**Solution:** For maximization problems, negate objective and minimize.

### 6. Forgetting Non-Negativity

**Problem:** Allows short-selling when not intended.

**Solution:** Always include non-negativity constraints:
```swift
let n = 3
var portfolioConstraints: [MultivariateConstraint<VectorN<Double>>] = [.budgetConstraint]
portfolioConstraints.append(contentsOf:
    MultivariateConstraint<VectorN<Double>>.nonNegativity(dimension: n)
)
```

## Performance Characteristics

### What Actually Costs Time

Absolute timings depend on the machine and, far more than most people expect, on
whether the library was built with optimizations. What is stable is the *ranking* of
the cost drivers, worst first:

| Driver | Effect | What to do about it |
|--------|--------|---------------------|
| A worst-case objective that is **linear in the decision variables** | Dominant. The inner BFGS loop never satisfies its stopping test, so it runs its full inner budget on every outer iteration | Add any strictly convex term — a variance penalty is usually already justified — or use a discrete set |
| **Sample count** `N` | Linear multiplier on every objective evaluation, and there are tens of thousands of them | Ask for the corner count when the objective is linear in ω (see Best Practice 5) |
| **Decision dimension** `d` | The numerical gradient costs `2d + 1` evaluations per BFGS step, and BFGS itself needs more steps as `d` grows | Aggregate similar assets before adding more |
| **Constraint count** | Linear, but small — every constraint is walked on every evaluation of the augmented Lagrangian | Drop constraints that are never active |

The first row is worth dwelling on, because it is counter-intuitive: the *easiest*
robust portfolio problem to write down — maximize the worst-case return, subject to a
budget and non-negativity — is the slowest one this solver runs. Its augmented
Lagrangian is scaled by a penalty parameter ρ that grows by a factor of ten per outer
iteration, while ``InequalityOptimizer``'s `gradientTolerance` is an *absolute* 1e-6,
so the inner loop's convergence test cannot be met once ρ reaches the millions. It
spends its whole 1000-iteration inner budget every time. Example 1's variance penalty
is not decoration; it is what makes that example finish in a fraction of a second
while the same problem without it takes seconds.

### Convergence Characteristics

**Typical outer iterations:** every example in this article converges in 1–6 outer
penalty iterations, and `maxIterations: 500` is nowhere near binding. If a problem
genuinely needs hundreds of *outer* iterations, the penalty schedule has overflowed
long before — look at the constraint scaling instead of raising the limit.

**Factors affecting convergence:**
- Smoothness of the worst-case objective (see above)
- Uncertainty set size (larger = harder)
- Constraint tightness
- Initial guess quality

### Scaling Guidelines

**Good performance:**
- Assets: ≤ 10
- Samples: 50-100
- Dimensions: ≤ 10

**Moderate performance:**
- Assets: 10-20
- Samples: 100-200
- Dimensions: 10-20

**May be slow:**
- Assets: > 20
- Samples: > 500
- Dimensions: > 20

For large problems, consider:
1. Reducing sample count
2. Using discrete scenarios instead of continuous
3. Aggregating similar assets
4. Using a two-stage approach (coarse then refined)

**Symptoms:**

- Memory usage high

**Solutions:**


```swift

```

4. **Reduce assets:**
```swift

```

### Problem: Different Results Each Run

**Symptoms:**
- Solution changes between runs
- Worst-case parameters different

**Cause:** Random sampling from the uncertainty set. ``BoxUncertaintySet`` and
``EllipsoidalUncertaintySet`` both draw their interior points with an unseeded
`Double.random`, and neither accepts a generator, so a solve cannot be made
bit-reproducible from the outside.

The box has an escape hatch the ellipsoid does not: its 2^d corners are enumerated
deterministically *before* any random point is drawn, so asking for exactly the corner
count produces no randomness at all. For an objective linear in ω that also costs
nothing in accuracy — which is why every box example in this article does it. An
ellipsoidal solve has no such option; expect its weights and its worst case to move
between runs.

**Solutions:**

1. **Request only the corners of a box:** `samplesPerIteration: 1 << d` draws no
   random points

2. **Accept minor variation:** for an ellipsoid, small differences are normal

3. **Use discrete uncertainty for reproducibility:**
```swift
func generateFixedScenarios() -> [[Double]] {
    [
        [0.05, 0.06, 0.04],
        [0.10, 0.12, 0.08],
        [0.16, 0.18, 0.13]
    ]
}

let fixedScenarios = generateFixedScenarios()
let reproducibleSet = try DiscreteUncertaintySet(points: fixedScenarios)
```

4. **Seed the generator:** not currently possible — ``UncertaintySet`` has no
   generator parameter on `samplePoints(numberOfSamples:)`

## Comparison with Other Optimization Approaches

### Robust vs Nominal Optimization

| Feature | Nominal | Robust |
|---------|---------|--------|
| **Uncertainty** | Ignored | Explicitly modeled |
| **Objective** | Point estimate | Worst-case |
| **Conservatism** | Not conservative | Conservative |
| **Complexity** | Lower | Higher |
| **Sensitivity** | High to errors | Low to errors |
| **Computational cost** | Low | Medium-High |

**When to use robust:**
- Parameter uncertainty significant
- Worst-case protection needed
- Conservative approach required

**When nominal suffices:**
- Parameters well-known
- Risk-neutral preferences
- Computational resources limited

### Robust vs Stochastic Optimization

| Feature | Stochastic | Robust |
|---------|------------|--------|
| **Uncertainty model** | Probability distribution | Uncertainty set |
| **Objective** | Expected value | Worst-case |
| **Data requirement** | Full distribution | Bounds/scenarios |
| **Confidence** | Probabilistic | Guaranteed |
| **Solution** | Risk-neutral | Conservative |

**When to use stochastic:**
- Good probabilistic models
- Expected value matters most
- Frequent repeated decisions

**When to use robust:**
- Limited statistical data
- Worst-case guarantees critical
- One-time high-stakes decision

### Robust vs Risk-Averse (Mean-Variance)

| Feature | Mean-Variance | Robust |
|---------|---------------|--------|
| **Risk measure** | Variance | Worst-case |
| **Objective** | Risk-adjusted return | Worst-case return |
| **Assumes** | Normal distribution | Bounded uncertainty |
| **Protects against** | Volatility | Extreme scenarios |

**When to use mean-variance:**
- Normal return distributions
- Symmetric risk concerns
- Variance is good risk proxy

**When to use robust:**
- Non-normal distributions
- Tail risk concerns
- Asymmetric downside focus

- Robust production planning under demand uncertainty
- Conservative asset allocation
- Scenario-based stress testing
- Risk-sensitive decision making

**Key Benefits:**
- **Guaranteed bounds:** Solutions work in all scenarios within uncertainty set
- **Conservative protection:** Shields against worst-case realizations
- **Flexible uncertainty:** Box, ellipsoidal, or discrete sets
- **Practical calibration:** Control conservatism through uncertainty set size

**Trade-offs:**
- More conservative than stochastic optimization
- Higher computational cost than nominal optimization
- Requires uncertainty set specification
- Sampling approximation (except discrete)
