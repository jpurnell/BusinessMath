## Overview

The module introduces three production-ready business optimization modules that make sophisticated constrained optimization accessible through domain-specific APIs. Each optimizer builds on the constrained optimization framework.

### What's Included

- **Resource Allocation Optimizer**: Capital budgeting, project selection, budget allocation
- **Production Planning Optimizer**: Multi-product manufacturing optimization
- **Financial Model Driver Optimizer**: Target seeking for financial goals

### Design Philosophy

Each optimizer follows a consistent pattern:
1. **Input Types**: Business-focused data structures (projects, products, drivers)
2. **Constraints**: Domain-specific constraint enums
3. **Objectives**: Multiple objective functions to choose from
4. **Results**: Rich result types with diagnostics

## Resource Allocation Optimizer

### What Problems Does It Solve?

- **Capital Budgeting**: Which projects should we fund with limited capital?
- **Budget Allocation**: How should we distribute budget across departments?
- **Marketing Mix**: How should we allocate marketing spend across channels?
- **Workforce Planning**: How should we assign employees to projects?

### Quick Start (5 lines)

> Important: Every budget, value and total in the resource-allocation examples is in **$ millions**,
> so `0.5` means $500,000, and printed money carries an `M` suffix. That is not cosmetic: these
> optimizers converge on absolute tolerances, so inputs scaled in raw dollars are both slower and
> less accurate. See [Units and Convergence](#units-and-convergence) for the measurements.

```swift
import BusinessMath

// Define investment options ($ millions)
let projects = [
    AllocationOption(
        id: "proj_a",
        name: "New Product Launch",
        expectedValue: 0.5,  // Expected NPV: $500K
        resourceRequirements: ["budget": 0.15]
    ),
    AllocationOption(
        id: "proj_b",
        name: "Marketing Campaign",
        expectedValue: 0.3,
        resourceRequirements: ["budget": 0.10]
    )
]

// Optimize allocation
let optimizer = ResourceAllocationOptimizer()
let result = try optimizer.optimize(
    options: projects,
    objective: .maximizeValue,
    constraints: [.totalBudget(0.2)]
)

print("Selected: \(result.selectedOptions.map { $0.name })")
print("Total value: \(result.totalValue.currency(2))M")
```

### Core Types

#### AllocationOption
Represents a project, investment, or option to allocate resources to.

```swift
    public let id: String                          // Unique identifier
    public let name: String                        // Human-readable name

    public let resourceRequirements: [String: Double]  // Resources needed
    public let strategicValue: Double?             // Optional strategic score (0-10)
    public let dependencies: Set<String>?          // Required prerequisites
```

**Example:**

```swift
    name: "Digital Transformation Initiative",
    expectedValue: 2.0,  // $2M NPV
    resourceRequirements: [
        "budget": 0.5,   // $500K
        "headcount": 15,
        "quarters": 4
    ],
    strategicValue: 9.5,
    dependencies: ["infrastructure_upgrade"]
)
```

#### AllocationConstraint
Business constraints on resource allocation.

<!-- docs:illustrative -->
```swift
public enum AllocationConstraint {
    case totalBudget(Double)                        // Maximum total budget
    case resourceLimit(resource: String, limit: Double)  // Max of specific resource
    case minimumAllocation(optionId: String, amount: Double)  // Min funding
    case maximumAllocation(optionId: String, amount: Double)  // Max funding
    case requiredOption(optionId: String)           // Must select
    case excludedOption(optionId: String)           // Cannot select
    case dependency(optionId: String, requires: String)  // If A then B
    case mutuallyExclusive([String])                // Only one from set
}
```

#### AllocationObjective
Objective functions for optimization.

<!-- docs:illustrative -->
```swift
public enum AllocationObjective {
    case maximizeValue                  // Maximize sum of expected values
    case maximizeValuePerDollar         // Maximize efficiency (value/cost)
    case maximizeWeightedValue(strategicWeight: Double)  // Blend value + strategic
    case maximizeRiskAdjustedValue(riskDiscount: Double)  // Discount for risk
    case custom((AllocationResult) -> Double)  // Custom objective
}
```

### Detailed Example: Capital Budgeting

A company has three candidate projects and a $1M budget. One project is mandatory, one depends on
it, and two of them cannot both be funded. Three options are enough to exercise that
required / dependent / mutually-exclusive combination; adding more only makes the example slower
to run, not clearer to read.

```swift
import BusinessMath

// Define all project options ($ millions)
let capitalProjects = [
	AllocationOption(
		id: "infrastructure",
		name: "Infrastructure Upgrade",
		expectedValue: 0.3,
		resourceRequirements: ["budget": 0.2, "headcount": 5],
		strategicValue: 8.0
	),
	AllocationOption(
		id: "new_product",
		name: "New Product Launch",
		expectedValue: 0.8,
		resourceRequirements: ["budget": 0.4, "headcount": 10],
		strategicValue: 9.0,
		dependencies: ["infrastructure"]  // Requires infrastructure
	),
	AllocationOption(
		id: "acquisition",
		name: "Strategic Acquisition",
		expectedValue: 1.0,
		resourceRequirements: ["budget": 0.6, "headcount": 8],
		strategicValue: 8.5
	)
]

// Define constraints
let capitalConstraints: [AllocationConstraint] = [
	.totalBudget(1.0),                            // $1M budget limit
	.resourceLimit(resource: "headcount", limit: 15),  // Max 15 people
	.requiredOption(optionId: "infrastructure"),  // Must upgrade infrastructure
	.mutuallyExclusive(["new_product", "acquisition"])  // Can't do both
]

// Optimize for financial value. `.maximizeWeightedValue(strategicWeight:)` would blend in the
// strategicValue scores instead — but read Units and Convergence first: the two terms have to
// be on the same numeric scale before the weight means what you think it means.
let capitalOptimizer = ResourceAllocationOptimizer()
let capitalResult = try capitalOptimizer.optimize(
	options: capitalProjects,
	objective: .maximizeValue,
	constraints: capitalConstraints
)

// Print results
print("=== Optimal Capital Allocation ===")
print("Total Value: \(capitalResult.totalValue.currency(2))M")
print("Converged: \(capitalResult.converged)")
print()

print("Selected Projects:")
for option in capitalResult.selectedOptions {
	let allocation = capitalResult.allocations[option.id] ?? 0
	print("  • \(option.name) - \(allocation.percent()) funded")
	print("    NPV: \(option.expectedValue.currency(2))M")
	print("    Budget: \((option.resourceRequirements["budget"] ?? 0).currency(2))M")
}

print()
print("Resource Usage:")
// Sort: dictionary order is not stable between runs, and documentation output should be.
for (resource, used) in capitalResult.totalResourcesUsed.sorted(by: { $0.key < $1.key }) {
	print("  • \(resource): \(used.number(2))")
}
```

## Production Planning Optimizer

### What Problems Does It Solve?

- **Production Scheduling**: What quantities should we produce?
- **Product Mix**: Which products should we prioritize?
- **Capacity Planning**: How can we maximize output given constraints?
- **Inventory Optimization**: Balance production costs vs holding costs

### Quick Start (5 lines)

```swift
import BusinessMath

// Define products to manufacture
let products = [
	ManufacturedProduct(
		id: "widget_a",
		name: "Widget A",
		pricePerUnit: 100,
		variableCostPerUnit: 45,
		demand: .unlimited,
		resourceRequirements: ["machine_hours": 2.0, "labor_hours": 1.0]
	),
	ManufacturedProduct(
		id: "widget_b",
		name: "Widget B",
		pricePerUnit: 80,
		variableCostPerUnit: 30,
		demand: .unlimited,
		resourceRequirements: ["machine_hours": 1.5, "labor_hours": 1.5]
	)
]

// Optimize production plan
let widgetOptimizer = ProductionPlanningOptimizer()
let plan = try widgetOptimizer.optimize(
	products: products,
	resources: ["machine_hours": 1000, "labor_hours": 800],
	objective: .maximizeProfit
)

print("Optimal Production:")
// Sort: dictionary order is not stable between runs, and documentation output should be.
for (productId, quantity) in plan.productionQuantities.sorted(by: { $0.key < $1.key }) {
	print("  \(productId): \(quantity.number(0)) units")
}
print("Total Profit: \(plan.profit.currency(2))")
```

```swift
    case maximizeProfit        // Revenue - costs

    case maximizeMargin        // (Revenue - costs) / Revenue

    case maximizeUtilization   // Use resources efficiently

```

### Detailed Example: Multi-Product Manufacturing

A manufacturer produces two product lines with different margins and resource requirements.

Prices here are per-unit dollars and quantities are units, so both are already close enough to 1
for the solver — the rescaling advice in [Units and Convergence](#units-and-convergence) is about
budgets and totals, not unit economics. What *does* cost you here is the number of decision
variables: each product added is another dimension in a numerically-differentiated gradient, and
the third product line this example used to carry multiplied its run time by roughly five.

```swift
import BusinessMath
// Define product catalog
let manufacturingProducts = [
 ManufacturedProduct(
	 id: "deluxe",
	 name: "Deluxe Model",
	 pricePerUnit: 250,
	 variableCostPerUnit: 120,
	 demand: .range(min: 50, max: 300),  // Must sell 50-300 units
	 resourceRequirements: [
		 "assembly_hours": 4.0,
		 "testing_hours": 2.0,
		 "materials_kg": 5.0
	 ]
 ),
 ManufacturedProduct(
	 id: "standard",
	 name: "Standard Model",
	 pricePerUnit: 150,
	 variableCostPerUnit: 70,
	 demand: .range(min: 100, max: 500),
	 resourceRequirements: [
		 "assembly_hours": 2.0,
		 "testing_hours": 1.0,
		 "materials_kg": 3.0
	 ]
 )
]

// Define available resources (monthly capacity)
let resources = [
 "assembly_hours": 2000.0,
 "testing_hours": 1000.0,
 "materials_kg": 4000.0
]

// Add production constraints
let manufacturingConstraints: [ProductionConstraint] = [
 .minimumProduction(productId: "deluxe", quantity: 60),  // Contractual obligation
 .productionRatio(productA: "deluxe", productB: "standard", ratio: 0.5)  // 1 deluxe per 2 standard
]

// Optimize for maximum profit
let manufacturingOptimizer = ProductionPlanningOptimizer(maxIterations: 300)
let manufacturingPlan = try manufacturingOptimizer.optimize(
 products: manufacturingProducts,
 resources: resources,
 objective: .maximizeProfit,
 constraints: manufacturingConstraints
)

// Display results
print("=== Optimal Production Plan ===")
print("Converged: \(manufacturingPlan.converged) (\(manufacturingPlan.iterations) iterations)")
print()

print("Production Quantities:")
for (productId, quantity) in manufacturingPlan.productionQuantities.sorted(by: { $0.key < $1.key }) {
 let product = manufacturingProducts.first { $0.id == productId }!
 let revenue = product.pricePerUnit * quantity
 let cost = product.variableCostPerUnit * quantity
 let profit = revenue - cost

 print("  • \(product.name): \(quantity.number(0)) units")
 print("    Revenue: \(revenue.currency(0)) | Cost: \(cost.currency(0)) | Profit: \(profit.currency(0))")
}

print()
print("Financial Summary:")
print("  Total Revenue: \(manufacturingPlan.revenue.currency(0))")
print("  Total Costs: \(manufacturingPlan.costs.currency(0))")
print("  Total Profit: \(manufacturingPlan.profit.currency(0))")
print("  Margin: \((manufacturingPlan.profit / manufacturingPlan.revenue).percent())")

print()
print("Resource Utilization:")
for (resource, utilization) in manufacturingPlan.resourceUtilization.sorted(by: { $0.key < $1.key }) {
 // Round rather than truncate: a binding constraint lands on 0.9999999 or 1.0000001
 // depending on the run, and truncation would turn that into 99% or 100% at random.
 let percentage = Int((utilization * 100).rounded())
 let bar = String(repeating: "█", count: percentage / 2)
 print("  • \(resource): \(percentage)% \(bar)")
}
```

### Changing the Objective

Every objective takes the same call — only the `objective:` argument moves. Here is
`.minimizeCosts`, which is only interesting when something holds production up from below: the
floor here is a minimum of 100 units each, above the Deluxe Model's contractual demand minimum
of 50.

```swift
// With minimum demand requirements
let minimumDemandConstraints = manufacturingProducts.map { product in
    ProductionConstraint.minimumProduction(
        productId: product.id,
        quantity: 100  // Must produce at least 100 of each
    )
}

let minimizeCostsPlan = try manufacturingOptimizer.optimize(
    products: manufacturingProducts,
    resources: resources,
    objective: .minimizeCosts,
    constraints: minimumDemandConstraints
)

print("=== Minimum-Cost Plan ===")
for (productId, quantity) in minimizeCostsPlan.productionQuantities.sorted(by: { $0.key < $1.key }) {
    print("  \(productId): \(quantity.number(0)) units")
}
print("  Total Costs: \(minimizeCostsPlan.costs.currency(0))")
```

The remaining objectives are the same substitution and are not re-solved here, because each extra
solve is seconds of run time that teaches nothing new:

- `.maximizeRevenue` — top-line growth, ignoring cost of goods
- `.maximizeMargin` — profit as a percentage of revenue rather than in absolute dollars
- `.maximizeUtilization` — keep machines and workers busy; note that this objective is often
  near-degenerate (many plans tie), so its solution can move slightly between runs

## Financial Model Driver Optimizer

### What Problems Does It Solve?

- **Target Seeking**: What operational changes hit our revenue target?
- **Scenario Planning**: Create realistic scenarios that achieve goals
- **Sensitivity Analysis**: Which drivers have the most impact?
- **Multi-Objective Planning**: Balance growth, profitability, and cash flow

### Quick Start (5 lines)

```swift
import BusinessMath

// Define operational drivers
let drivers = [
	OptimizableDriver(
		name: "price",
		currentValue: 100,
		range: 80...120,
		changeConstraint: .percentageChange(max: 0.15)  // Max 15% change
	),
	OptimizableDriver(
		name: "volume",
		currentValue: 1000,
		range: 800...1500
	)
]

// Define financial target
let targets = [
	FinancialTarget(
		metric: "revenue",
		target: .minimum(120_000),
		weight: 1.0
	)
]

// Optimize drivers to hit target
let revenueOptimizer = DriverOptimizer()
let revenueResult = try revenueOptimizer.optimize(
	drivers: drivers,
	targets: targets,
	model: { driverValues in
		let price = driverValues["price"]!
		let volume = driverValues["volume"]!
		return ["revenue": price * volume]
	}
)

print("Optimized Drivers:")
// Sort: dictionary order is not stable between runs, and documentation output should be.
for (name, value) in revenueResult.optimizedDrivers.sorted(by: { $0.key < $1.key }) {
	let change = revenueResult.driverChanges[name]!
	print("  \(name): \(value.number(2)) (change: \(change > 0 ? "+" : "")\(change.number(0)))")
}
print("Revenue: \(revenueResult.achievedMetrics["revenue"]!.currency(0))")
```

#### OptimizableDriver
Represents an operational driver that can be optimized.

### Detailed Example: SaaS MRR Optimization

A SaaS company wants to hit $60K MRR by optimizing price, churn, and new customer acquisition.

```swift
import BusinessMath

// Define SaaS operational drivers
let saasDrivers = [
	OptimizableDriver(
		name: "price_per_seat",
		currentValue: 50,
		range: 40...70,
		changeConstraint: .percentageChange(max: 0.20)  // Max 20% price change
	),
	OptimizableDriver(
		name: "monthly_churn_rate",
		currentValue: 0.05,  // 5% monthly churn
		range: 0.02...0.08,
		changeConstraint: .absoluteChange(max: 0.015)  // Max 1.5% change
	),
	OptimizableDriver(
		name: "new_customers_per_month",
		currentValue: 100,
		range: 80...150
	)
]

// Define financial targets (multiple goals)
let saasTargets = [
	FinancialTarget(
		metric: "mrr",
		target: .minimum(60_000),
		weight: 2.0  // High priority
	),
	FinancialTarget(
		metric: "customer_count",
		target: .minimum(1000),
		weight: 1.0
	),
	FinancialTarget(
		metric: "customer_lifetime_value",
		target: .minimum(1000),
		weight: 1.0
	)
]

// Define SaaS financial model
let saasModel: @Sendable ([String: Double]) -> [String: Double] = { driverValues in
	let pricePerSeat = driverValues["price_per_seat"]!
	let churnRate = driverValues["monthly_churn_rate"]!
	let newCustomersMonthly = driverValues["new_customers_per_month"]!

	// Steady-state calculations
	let steadyStateCustomers = newCustomersMonthly / churnRate
	let mrr = steadyStateCustomers * pricePerSeat
	let avgLifetimeMonths = 1.0 / churnRate
	let ltv = pricePerSeat * avgLifetimeMonths * 0.7  // 70% gross margin

	return [
		"mrr": mrr,
		"customer_count": steadyStateCustomers,
		"customer_lifetime_value": ltv
	]
}

// Optimize drivers to hit targets (minimize changes)
let saasOptimizer = DriverOptimizer(maxIterations: 300)
let saasResult = try saasOptimizer.optimize(
	drivers: saasDrivers,
	targets: saasTargets,
	model: saasModel,
	objective: .minimizeChange  // Minimal changes from current
)

// Display results
print("=== SaaS MRR Optimization ===")
print("Feasible: \(saasResult.feasible)")
print("Converged: \(saasResult.converged) (\(saasResult.iterations) iterations)")
print()

print("Optimized Drivers:")
for driver in saasDrivers {
	let current = driver.currentValue
	let optimized = saasResult.optimizedDrivers[driver.name]!
	let change = saasResult.driverChanges[driver.name]!

	print("  • \(driver.name):")
	print("    Current: \(current)")
	print("    Optimized: \(optimized.number(2))")
	print("    Change: \(change.number(2)) (\((change / current).percent()))")
}

print()
print("Achieved Metrics:")
for target in saasTargets {
	let achieved = saasResult.achievedMetrics[target.metric]!
	let fulfilled = saasResult.targetsFulfilled[target.metric]!
	let symbol = fulfilled ? "✓" : "✗"

	print("  \(symbol) \(target.metric): \(achieved.number(0))")

	switch target.target {
	case .minimum(let min):
			print("    Target: ≥ \(min.number(0))")
	case .maximum(let max):
			print("    Target: ≤ \(max.number(0))")
	case .exact(let value):
			print("    Target: = \(value.number(0))")
	case .range(let min, let max):
			print("    Target: \(min.number(0)) - \(max.number(0))")
	}
}
```

### Common Use Cases

#### 1. E-commerce Conversion Optimization
```swift
let ecommerceDrivers = [
	OptimizableDriver(name: "product_price", currentValue: 100, range: 80...150),
	OptimizableDriver(name: "conversion_rate", currentValue: 0.03, range: 0.02...0.05),
	OptimizableDriver(name: "traffic", currentValue: 10_000, range: 8_000...15_000)
]

let ecommerceTargets = [
	FinancialTarget(metric: "revenue", target: .minimum(35_000), weight: 2.0),
	FinancialTarget(metric: "orders", target: .minimum(300), weight: 1.0)
]

let ecommerceOptimizer = DriverOptimizer(maxIterations: 300)

let ecommerceResult = try ecommerceOptimizer.optimize(
	drivers: ecommerceDrivers,
	targets: ecommerceTargets,
	model: { values in
		let price = values["product_price"]!
		let conversion = values["conversion_rate"]!
		let traffic = values["traffic"]!

		// Price elasticity effect
		let priceImpact = 1.0 - (price - 100) / 200.0
		let effectiveConversion = conversion * max(0.5, priceImpact)

		let orders = traffic * effectiveConversion
		let revenue = orders * price

		return ["revenue": revenue, "orders": orders]
	}
)

print("Orders:\t\t\(ecommerceResult.achievedMetrics["orders"]!.rounded(.down))")
print("Revenue:\t\(ecommerceResult.achievedMetrics["revenue"]!.currency())")
```

#### 2. Cost-Weighted Optimization
When some drivers are more expensive to change than others:

```swift
// SaaS business model with different cost drivers
let costWeightedDrivers = [
	OptimizableDriver(name: "price", currentValue: 50, range: 40...80),
	OptimizableDriver(name: "headcount", currentValue: 100, range: 80...150),
	OptimizableDriver(name: "churn_rate", currentValue: 0.05, range: 0.02...0.08)
]

let costWeightedTargets = [
	FinancialTarget(metric: "arr", target: .minimum(6_000_000), weight: 1.0),
	FinancialTarget(metric: "profit_margin", target: .minimum(0.20), weight: 1.0)
]

// Cost to change each driver
let costs = [
	"price": 1.0,           // Easy to change (just update pricing)
	"headcount": 50_000.0,  // Very expensive (recruiting, onboarding, severance)
	"churn_rate": 10_000.0  // Moderate (customer success programs)
]

let costWeightedOptimizer = DriverOptimizer(maxIterations: 300)

let costWeightedResult = try costWeightedOptimizer.optimize(
	drivers: costWeightedDrivers,
	targets: costWeightedTargets,
	model: { values in
		let price = values["price"]!
		let headcount = values["headcount"]!
		let churnRate = values["churn_rate"]!

		// ARR model
		let customers = 100_000.0
		let retention = 1.0 - churnRate
		let arr = customers * retention * price * 12

		// Costs
		let salaries = headcount * 120_000  // Average salary
		let otherCosts = 2_000_000.0
		let totalCosts = salaries + otherCosts

		let profit = arr - totalCosts
		let profitMargin = profit / arr

		return [
			"arr": arr,
			"profit_margin": profitMargin,
			"total_costs": totalCosts
		]
	},
	objective: .minimizeCost(costs)  // Prefer changing cheaper drivers
)

print("Optimized Solution:")
print("  Price: $\(costWeightedResult.optimizedDrivers["price"]!.number(2))")
print("  Headcount: \(Int(costWeightedResult.optimizedDrivers["headcount"]!))")
print("  Churn Rate: \(costWeightedResult.optimizedDrivers["churn_rate"]!.percent())")
print("\nResults:")
print("  ARR: \(costWeightedResult.achievedMetrics["arr"]!.currency())")
print("  Profit Margin: \(costWeightedResult.achievedMetrics["profit_margin"]!.percent())")
print("  Total Operating Costs: \(costWeightedResult.achievedMetrics["total_costs"]!.currency())")
```

### Integration with Financial Model

The `FinancialModel` type uses a declarative result builder pattern for defining revenue and costs. You can use the driver optimizer to find operational parameters that hit your financial targets, then incorporate those into your model.

```swift
import BusinessMath

// Step 1: Use driver optimizer to find optimal pricing and churn
let modelDrivers = [
    OptimizableDriver(name: "price", currentValue: 50, range: 40...70),
    OptimizableDriver(name: "churn", currentValue: 0.05, range: 0.02...0.08)
]

let modelTargets = [
    FinancialTarget(metric: "mrr", target: .exact(100_000), weight: 1.0)
]

let modelOptimizer = DriverOptimizer()
let modelResult = try modelOptimizer.optimize(
    drivers: modelDrivers,
    targets: modelTargets,
    model: { values in
        let price = values["price"]!
        let churn = values["churn"]!
        let newCustomers = 150.0  // Fixed acquisition rate

        let steadyStateCustomers = newCustomers / churn
        let mrr = steadyStateCustomers * price

        return ["mrr": mrr]
    }
)

// Step 2: Build a financial model using the optimized parameters
if modelResult.feasible {
    let optimizedPrice = modelResult.optimizedDrivers["price"]!
    let optimizedChurn = modelResult.optimizedDrivers["churn"]!
    let customers = 150.0 / optimizedChurn  // Steady-state customers

    let model = FinancialModel {
        Revenue {
            Product("SaaS Subscriptions")
                .price(optimizedPrice)
                .customers(customers)
        }

        Costs {
            Fixed("Salaries", 50_000)
            Fixed("Infrastructure", 10_000)
            Variable("Customer Support", 0.15)  // 15% of revenue
        }
    }

    print("Optimized Model:")
    print("  Revenue: $\(Int(model.calculateRevenue()))")
    print("  Costs: $\(Int(model.calculateCosts(revenue: model.calculateRevenue())))")
    print("  Profit: $\(Int(model.calculateProfit()))")
}
```

## Troubleshooting

### Resource Allocation

**Problem: Optimizer returns no selected options**
```
Solution: Check if constraints are too restrictive. Try relaxing budget or resource limits.
```

**Problem: Required option not selected despite constraint**
```
Solution: The required option may be infeasible with other constraints. Check dependencies
and ensure sufficient budget for required options plus their prerequisites.
```

**Problem: All options get partial allocation**
```
Solution: Partial allocation is legitimate - values range from 0 (none) to 1 (full), and
options above 0.01 count as "selected". Use a higher threshold if you want binary decisions.

But check your units first. Awkward fractions like 0.8331 / 0.7503 where you expected
1.0 / 0.5 are the signature of an optimizer that stopped short because its absolute
tolerance was unreachable at your scale. See Best Practices > Units and Convergence.
```

### Production Planning

**Problem: Utilization is low despite unlimited demand**
```
Solution: Check if variable costs exceed prices (negative contribution margin). The optimizer
won't produce products with negative margins even with unlimited demand.
```

**Problem: Minimum demand constraints not satisfied**
```
Solution: The problem may be infeasible. Check that available resources can support minimum
demand for all products. Try increasing resource capacity or relaxing constraints.
```

**Problem: Optimization doesn't converge**
```
Solution: Try increasing maxIterations when creating the optimizer:
  let optimizer = ProductionPlanningOptimizer(maxIterations: 500)

Also check for conflicting constraints (e.g., production ratio + minimum quantities).
```

### Driver Optimization

**Problem: Targets not achieved (feasible = false)**
```
Solution: The targets may be mathematically impossible with the given driver ranges and
constraints. Try:
  1. Widening driver ranges
  2. Relaxing change constraints
  3. Adjusting target values
  4. Adding more drivers to optimize
```

**Problem: Drivers don't change from current values**
```
Solution: Check that:
  1. Target is not already met with current drivers
  2. Change constraints aren't too tight (e.g., max 1% change)
  3. Driver ranges include current values
  4. Model function correctly uses driver values
```

**Problem: Optimization is slow**
```
Solution: In order of how much they usually buy you:
  1. Rescale. The convergence tolerances are absolute, so money in raw dollars keeps the
     inner solver from ever meeting them. Scale budgets, values and targets to $ millions.
     See Best Practices > Units and Convergence.
  2. Start with fewer drivers (2-3). Gradients are numerical, so cost grows with dimension.
  3. Simplify the model function - it is evaluated 2 x (number of drivers) times per
     gradient, and there are up to 1,000 gradients per outer iteration.

Note what is NOT on this list: lowering maxIterations. That truncates the outer penalty
loop rather than converging it, and returns an unconverged answer that still reports a
number. Check `converged` before you trust a result.
```

## Best Practices

### General Guidelines

1. **Start Simple**: Begin with a minimal example and gradually add complexity
2. **Validate Inputs**: Check that constraints are feasible before optimizing
3. **Test Edge Cases**: Try with extreme values to understand behavior
4. **Monitor Convergence**: Check the `converged` flag and `iterations` count
5. **Iterate**: Start with relaxed constraints and tighten as needed
6. **Mind Your Units**: see below — this is the single biggest lever on both speed and accuracy

### Units and Convergence

All three optimizers run an augmented-Lagrangian loop over a BFGS inner solver, and **both of its
convergence tolerances are absolute, not relative**: the inner solver stops when the gradient norm
drops below `1e-6`, and the outer loop stops when the largest constraint violation drops below
`1e-6`. Neither is scaled to the size of your numbers.

That makes the units you write the model in part of the model. Gradients are computed by finite
differences, so their own numerical error grows with the magnitude of the objective. An objective
scaled in raw dollars has gradients in the hundreds of thousands and a gradient *error* far above
`1e-6` — the tolerance is unreachable, so the inner solver never stops early and spends its full
iteration budget on every outer iteration. Rescaled to $ millions, the same problem has gradients
near 1, the tolerance becomes reachable, and the solver stops when it is genuinely done.

The two-project quick start at the top of this article, written three ways — same problem, same
optimizer, only the units differ:

```
units       inputs (value A / budget)   relative time   allocation A / B
dollars     500_000 / 200_000                    3.4x   0.8331 / 0.7503
thousands   500 / 200                            1.9x   0.9982 / 0.5027
millions    0.5 / 0.2                            1.0x   1.0000 / 0.5000
```

The dollar-scaled run is not merely 3.4x slower. It is also wrong: the true optimum funds project A
in full and project B at half, and only the millions-scaled run finds it. The other two stop while
the gradient is still large and report whatever iterate they happened to be on.

**Recommendation: scale money so the numbers the optimizer sees sit near 1.** Use $ millions for
the values and budgets you hand `ResourceAllocationOptimizer`, keep constraint bounds in the same
range, and carry the unit in your labels rather than in the data. Per-unit prices and physical
quantities — the inputs to `ProductionPlanningOptimizer` — are usually already near that range and
need no change.

`DriverOptimizer` is less exposed. Its constraints are the driver ranges themselves — prices,
rates, headcounts — which already sit near unit scale, and its financial targets enter the
objective as a penalty that falls to zero once the target is met. That is why the SaaS example
earlier keeps an MRR target in raw dollars and still converges in a single outer iteration. If a driver
model *is* slow, check whether a target is being missed by a large absolute margin: that miss is
squared before it reaches the objective.

The same rule governs *blended* objectives. `.maximizeWeightedValue(strategicWeight: w)` computes
`(1 - w) × expectedValue + w × strategicValue`. With `expectedValue` in raw dollars a 0–10
strategic score is rounding error and the weight does nothing; with `expectedValue` in $ millions
the same score dominates. Put both terms on a comparable numeric scale before you trust `w`.

### Model Functions

```swift
// Good: Simple, clear model
let model: ([String: Double]) -> [String: Double] = { drivers in
    let price = drivers["price"]!
    let volume = drivers["volume"]!
    return ["revenue": price * volume]
}

// Better: Include business logic
let elasticityModel: ([String: Double]) -> [String: Double] = { drivers in
    let price = drivers["price"]!
    let volume = drivers["volume"]!

    // Price elasticity: higher price reduces volume
    let elasticity = -0.5
    let priceChange = (price - 100) / 100
    let adjustedVolume = volume * (1 + elasticity * priceChange)

    return ["revenue": price * adjustedVolume]
}

// Best: Comprehensive financial model
let comprehensiveModel: ([String: Double]) -> [String: Double] = { drivers in
    let price = drivers["price"]!
    let churn = drivers["churn_rate"]!
    let newCustomers = drivers["new_customers"]!

    // Steady-state metrics
    let customers = newCustomers / churn
    let mrr = customers * price
    let ltv = (price / churn) * 0.7  // 70% margin
    let cac = 50.0  // Assumed
    let ltvCacRatio = ltv / cac

    return [
        "mrr": mrr,
        "customers": customers,
        "ltv": ltv,
        "ltv_cac_ratio": ltvCacRatio
    ]
}
```
