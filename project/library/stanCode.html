Simulating from and checking a model in Stan: It’s so easy in Stan Playground–it just runs on your browser!

Posted on December 15, 2025 4:34 PM by Andrew

When building models, it’s helpful to check our understanding by simulating fake data and seeing if the fitted model can recover the true underlying parameters. And it’s so easy to do in Stan!

See above–I just did a simple example in Stan Playground . (Thanks, Brian!) The code’s kind of ugly because I specified the true parameter values in the transformed data block Stan code rather than calling them as data; on the upside the whole thing is then in one program.

This is not the same as full simulation-based calibration checking (SBC). In SBC you draw the true parameter values from the prior, repeat the entire process in parallel many times, and then check the average coverage of posterior inferences with respect to the true parameter values, averaging over the prior. Here I’m just running one simulation and setting the true parameter values just once. It’s a kind of quick-and-dirty SBC which can still be useful in catching problems such as nonidentified models or poor mixing.

And it’s so easy to do! Whenever you fit a model, you should be checking it on fake data.

I was doing the above example because I wanted to quickly check for one of the exercises I’m writing for the forthcoming Bayesian Workflow book.

P.S. Here’s the code for the above example if you want to try it yourself: 

                            transformed data {
                              int N = 100;
                              real a_true = 0.2;
                              real b_true = 0.3;
                              real sigma_true = 0.2;
                              vector[N] x;
                              vector[N] y;
                               for (n in 1:N) {
                                x[n] = uniform_rng(0, 10);
                                y[n] = normal_rng(1 / (a_true + b_true * x[n]), sigma_true);
                              }
                            }
                            parameters {
                              real<lower=0> a, b, sigma;
                            }
                            model {
                              a ~ normal(0, 1);
                              b ~ normal(0, 1);
                              for (n in 1:N) {
                                y[n] ~ normal(1 / (a + b * x[n]), sigma);
                              }
                            }

    • Andrew on December 15, 2025 5:50 PM at 5:50 pm said:

      Cedric:

      Model fits can fail all the time! As a simple illustration, try the above example with flat priors on a and b and it will indeed blow up.

      More generally, every fitting algorithm I’ve ever seen can have problems. Whether you’re using Hamiltonian Monte Carlo or variational inference or expectation propagation or nested Laplace or just plain optimization, we frequently run into real-world problems where the models don’t fit, sometimes because of poor mixing (the algorithms don’t do a good job of traversing parameter space), sometimes because of poor identification (the target function (in a Bayesian context, the unnormalized posterior density) has an infinite integral or includes all sorts of weird faraway regions, sometimes because the mode of the target function is degenerate (when you’re doing optimization), sometimes because the approximations in the approximation part of your algorithm (for variational inference or expectation propagation) are too approximate, sometimes because there’s a bug in your modeling code, . . . all sorts of reasons!

      If your program can fit data simulated from the model, that doesn’t demonstrate that it’s a good model or that it will fit well with real data. It’s a minimum check. If you’re program can’t fit data simulated from the model, then that’s something that you’ll want to know right away. And, given that this happens often, it makes sense to do the check.

      Beyond all that, I find fake-data simulation helpful because it can clarify what I’m doing with my model. The thing about fake-data simulation is that it’s generative. Often we can write a model and it kinda looks ok, both in math and in code, but then when we try to simulate from it generatively, we realize it’s missing some pieces.
