## Architectural Decisions

Memorialized in `Instruction Set/development-guidelines/rules/10_ARCHITECTURE_DECISIONS.md`:

| ADR | Decision | Why |
|---|---|---|
| **ADR-001** | Add `Vector1D<T>` to complete the vector type family | Closes a structural gap (Vector2D/3D/VectorN existed but no Vector1D), enables single Interpolator protocol, ~30 lines, side benefit of letting future generic-over-VectorSpace optimizers include the 1D case |
| **ADR-002** | Single `Interpolator` protocol with `Point: VectorSpace` and `Value: Sendable` associated types | Rejected a 4-protocol hierarchy (more cognitive overhead), VectorN with runtime dim checking (loses compile-time safety), and wrapping scalars in trivial VectorSpace types (ceremony with no benefit) |
| **ADR-003** | Multi-version roadmap for ND interpolation (1D in v2.1.2, 2D in v2.2, 3D and ND gridded in v2.3, ND scattered in v2.4) | Architects for ND from day one without overcommitting; each phase aligns with natural design boundaries |
| **ADR-004** | Ten-method set + parameter defaults: makima `true`, CatmullRom tension `0` (corrected from initial 0.5), BSpline degree default 3 max 5, ExtrapolationPolicy default `.clamp` | Comparable in scope to scipy.interpolate's 1D coverage; defaults match the literature and pass property tests |

## Bugs Caught and Fixed

### Caught BEFORE writing package code (by validation playground)

1. **`NextValue` at exact knots was returning `ys[i+1]` instead of `ys[i]`.** The pass-through invariant property check failed in the playground at every interior knot. Fixed in playground first, then enforced in package implementation with a regression test.

2. **`CatmullRom` default tension was 0.5 in the original ADR-004**, which is half-strength tangents and fails the linear-data invariant by 12.6% relative error. Standard Catmull-Rom is `τ = 0` (full-strength tangents), which passes at machine precision (~3.5e-15). I had conflated cardinal-spline tension (τ=0 is Catmull-Rom) with the centripetal Catmull-Rom alpha parameter (which only applies to parametric curves in 2D/3D). ADR-004 amended; default corrected; both the playground and the package implementation use the corrected default.

### Caught DURING test execution

3. **`PreviousValueInterpolator` at the last exact knot was returning `ys[n-2]`** instead of `ys[n-1]`. Root cause: my `extrapolatedValue` helper returns nil for in-range queries (including the boundary), so at `t == xs[n-1]` the function fell through to `bracket` which returned `(n-2, n-1)` and then took `ys[lo] = ys[n-2]`. Fixed with a special-case check for `t == xs[hi]` after bracket lookup. Regression test included.

### Caught by CI (release-build optimization)

4. **Swift compiler "unable to type-check expression in reasonable time"** in release builds for the CubicSpline evaluation expression and the cubicHermite helper. Debug builds passed because they use less aggressive type-checking. Fixed by binding each multiplicative term to its own `let` so the type checker handles them individually. Mathematically identical, just explicit about evaluation order.

## Findings to Surface for v2.1.3

The v2.1.2 work surfaced two pre-existing issues that should be cleaned up
in v2.1.3 (a "dev hygiene" patch release):

1. **13 source files have `String(format:)` violations** (40 call sites in
   Sources/), plus 4 test files and 2 examples, all of which violate the
   project's Forbidden Patterns rule. Now that the rule is in the prominent
   Forbidden Patterns table at the top of `coding_rules.md` and a
   quality-gate check is filed at `quality-gate-swift/.../UPCOMING/StringFormatDetection.md`,
   the existing violations need to be cleaned up so the new check doesn't
   fail with 40 hits the moment it ships.

2. **Pre-existing flaky test** `PortfolioUtilitiesTests.Random returns are
   within reasonable range` uses unseeded randomness, violating BusinessMath's
   own mandatory rule from `test_driven_development.md`. Observed one
   failure during v2.1.1 development. Fix is ~10 lines: thread a seeded
   `DeterministicRNG` through the test.

3. **Two existing tests are too loose:**
   - `accelerateMatchesPureSwift` only checks peak bin location, missed the
     v2.1.0 4× scaling bug. Should assert absolute equivalence.
   - `parsevalsTheorem` uses tolerance 0.5 < ratio < 2.0 (so loose it would
     pass with major numerical bugs). Should be tightened.

These are all "consequences of v2.1.1/v2.1.2 work surfaced but not fixed in
those releases." Bundling them as v2.1.3 is cleaner than letting them rot.

## Context Loss Warnings

For the next session that picks this up cold:

- **The single Interpolator protocol with associated types is a
  forward-compatibility commitment.** When 2D gridded interpolators land in
  v2.2, they MUST conform to the same `Interpolator` protocol with
  `Point = Vector2D<T>`. Don't introduce a parallel Interpolator2D protocol.
- **The validation playground is the source of truth for test reference
  values.** When you change a method's algorithm, run the playground first,
  verify the new values are still correct, then update test assertions.
- **The cubic Hermite evaluator is shared by PCHIP, Akima, and CatmullRom**
  via the internal `cubicHermite(t:xs:ys:slopes:)` function in PCHIP.swift.
  Changes to this evaluator affect all three methods.
- **Release-build type-checker timeouts** are a real constraint on cubic
  spline expressions. Always break long expressions into intermediate `let`
  bindings if you touch the evaluation paths.
- **CatmullRom default tension is 0, NOT 0.5.** This was corrected during
  v2.1.2 development after the playground caught the bug. ADR-004 has the
  correction documented.
