## Deviations from the brief

1. **Return type is `ComponentwiseScores`, not `DiagnosedScores`.** The stored payload has four keys (`scores`, `convergence`, `components`, `isolatedCount`); `DiagnosedScores` has two and widening it changes a shape three metrics store.
   `ComponentwiseScores.diagnosed` gives the plain `DiagnosedScores` view; the payload decodes as `DiagnosedScores` and `NodeScores`.
2. **`GoldenRecordData.swift` was edited** (a third deliberate edit after ADR-009's two): registering the metric in `standard` changed the stored registry listing, the per-fixture records and the integer-node tokens, so the new metric's entries were added
   (generated by ClassGraph's code) and the eleven existing entries are untouched. Three existing tests that counted the registry (11) now say 12.
3. Parity is asserted to a tolerance, not byte for byte, for four decimal-weight cases, because of a pre-existing non-determinism (below).

## Findings, not changed (open decisions)

- **`WeightedGraph.totalWeight` is summed in dictionary order**, so for weights that are not binary fractions the last bit of a score can differ between processes (seen in 2 of the generator's cases in 12 runs). It feeds the iteration shift, so every weighted measure on a graph with real-valued weights is affected, including the stored `eigenvector-centrality` records. Fix would be a sorted summation in `WeightedGraph.init`; it changes bits of existing results, so it needs its own decision and, probably, version bumps.
- **Overflow**: for weights of about 1e154 and above `eigenvectorConvergence` returns all zeros reported as converged; by component such a component scores 0, keeps scale 1, is not counted as isolated. ClassGraph's mutation notes call the guards that handle it unreachable; they are reachable. Documented in the DocC and pinned (as a limit, not a feature) by `EigenvectorByComponentOverflowTests`. Underflow below about 1e-200 gives all ones.
- **Name overlap with ClassGraph** while both copies exist: a file importing BusinessMath whole and ClassGraphMetrics sees two `ComponentwiseScores`, `ComponentScoring`, `ComponentwiseEigenvectorMetric`. Its cutover deletes its copy (or keeps the `String` alias style it uses for the five existing types).
- The cross-component scale is a convention; changing it is a version 2, not an edit.
